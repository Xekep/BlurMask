# Actual fresh Math candidate and temporary-field publication

`Math2Mode0FreshMathPublisher.Create(actualProducedReceipt)` now joins actual
full EE4/C79/first-copy output to a Math-specific temporary document and its
late registered selections. This is an internal library semantic publisher.
It does not accept an original SDK page, native patch ABI, pending CBB receiver
or history transaction, and it does not change the application recognizer.
It is not formula layout, evaluation or accepted original-page content.

## Exact source and lock order

The input is the existing PRODUCED `Math2Mode0SelectedMathFieldCopy` receipt.
Callers cannot supply strings, candidate rows, ranges, tag tables, registry
IDs/counters, DOM nodes or success flags to the production factory. The
receipt validates the exact field and first copy before the field gate is
entered. The field's new trusted accessor checks the same receipt.Field,
active pre-NN binding, prepared source, live copy pool, exact Document,
selected INPUT0/category102/C22/full range and Next1. Prior results or an
inconsistent registry are refused as a whole.

The accessor NEVER enters the receipt gate while holding the field gate;
this avoids the inverse of receipt validation's receipt-to-field lock order.
The trusted source view is used only while the actual field gate remains
held. It derives the selected mathField node identity from its retained field
id and checks that field's input/tag against the same actual registry entry.
The kernel receives that readonly identity and clones its subtree, without
substituting a hard-coded scaffold node number.
It passes actual selected nodes/ranges/Next and a liveness check to
the new kernel, not a public replacement-source constructor. The original
source, selected registry and nodes remain unchanged; their real shared name
owner may intern new candidate names as native temporary BCCs do.

A new ConditionalWeakTable holds a single-use claim for each actual receipt.
Budget, domain and preentry cancellation checks precede that claim. Competing
factory calls on the same receipt yield exactly one completed publisher and
one refusal. Entered failures poison the new target and consume that receipt;
they cannot be retried as a fresh publication.

The publisher borrows the receipt and its first copy. It creates and owns
its outer vector internally from THAT copy. It never disposes the borrowed
copy or receipt. Source/receipt close invalidates new entry and is rechecked
at semantic construction/mutation boundaries. An already active operation
is not an asynchronous native-call interruption guarantee.

## Third registry and two DOM arenas

The publisher creates a distinct third Ink/registry identity and clones the
actual selected INPUT0/C22/Next1. New Math selections mutate this third
registry. They do not overwrite the selected NN/C23 registry, reuse raw source
IDs as selection IDs, or fabricate a textField/category100 owner. The immutable
raw Document is shared as a library semantic geometry owner; the native C20
allocator/observer graph is not reproduced.

Only the actual selected mathField subtree is cloned under the temporary
BCC's generic root; the surrounding selected PAGE/content/layout scaffold
is not copied. Source-node origins and attributes-before-children clone order
are retained. That field and a new empty mathResult belong to the temporary
field arena. The candidate mathResult belongs to another arena. Both retain
the actual selected DOM name owner. The candidate contains sequence/symbol
nodes, symbolSegmentList/symbolSegment/symbolCandidate/char metadata, and a
mathTerminalNode. Every actual retained first-copy symbol is processed; an
unsupported entire vector is refused rather than selecting an easier result.

Each nonempty symbol range is serialized with the existing checked C21
formatter using original source IDs and fractions. It gets a CB8 pending
`MATH_SYMBOL` entry and a negative INT64 tag. The text node uses the first
alternative's C-string bytes through strict UTF8 conversion, with no joining
spaces, score calibration or
table-marker interpretation. Empty source-range rows bypass range/tag work.
Invalid UTF8 byte intervals are explicitly refused by this library scope;
native byte-copy acceptance of arbitrary invalid strings is not claimed.
The admitted source owns ordinary raw C49/full identity views and no prior
mathResult, so the actual fresh transform/freeze defaults are empty; arbitrary
imported/C25/nonidentity/prior state is not admitted.

The full INPUT range supplies symbolSegment.range and mathTerminalNode.ref.
`nrs` stores FLOAT32 positive0 (type10), `selected` stores INT32 0 (type7),
and tag stores INT64 (type4). mathTerminalNode.name is an empty string. Native
0EB740 distinguishes empty string type3 from short nonempty type2 and long
type1, and the publisher preserves that distinction. The literal placeholder
char is `?`; this fallback metadata is not a recognized semantic formula.

Temporary IDs start at2. An entry is linked with unresolved ID-1 and its own
C22 range copy. An explicit prepared C22-clone refusal consumes/links the
temporary ID before refusing; it does not allocate a final registry ID.
The production route accepts no caller failure flag; the optional failure
index is internal diagnostic scaffolding only.

## Produced ordered patch and late tags

The actual candidate root has three children: sequence, symbolSegmentList
and mathTerminalNode. The actual temporary root is empty. The verified default
BE0 empty-old reduction produces three opcode2 insertions with ordinals0/1/2.
Each complete candidate child subtree is recursively cloned into the SAME
temporary arena before its action is queued. All three payloads are cloned
before any action is applied. Snapshot IDs expose each candidate/payload
root and clone origin, so replacing them with a detached tag list would fail
verification.

CB8's native special tag filter acts only on opcode7; these actual fresh
actions are opcode2 and remain in order. Application appends each cloned
payload to the retained temporary mathResult. Only after the full application
does the logical action header become non-live. This is an explicit library
ordered patch, not exported native40-byte patch storage or a claim to preserve
all native observers/refcounts.

Late resolution walks the TAG ATTRIBUTES OF THOSE INSERTED TEMPORARY NODES.
Each negative tag locates its exact pending entry, registers its stored
name/ranges as category102 against the third registry, caches the returned
ID, then writes that ID to the actual INT64 attribute. Registry advancement
and resolved-cache state occur before the tag-write boundary; a later failure
does not erase them. The new tag vector preserves traversal order and
duplicates. The actual fresh old result has no old tags, so V50's stale loop
has nothing to delete. General nonempty-prior deletion/reuse is not claimed.

The owned outer pool and logical batch resources are cleaned once after
publication or explicit disposal. Candidate/temp nodes, ranges and state are
retained as bounded semantic result/diagnostic data, independent of the disposed
decoder/model/source. Diagnostic reads deep-copy arrays. Source or receipt
closure revokes CopyResult authority without erasing already copied snapshots.

## Budget and failures

Before payload copies the factory reserves a conservative complete-chain
envelope: existing first-copy reservation,8192 base bytes,1536 per symbol,
32 times interval bytes,512 per symbol range and1024 per INPUT range. It
covers the new outer/vector/string pool, candidate/temp trees, cloned action
payloads, names, C22 copies and retained semantic diagnostics. Its ceiling is
16MiB. It describes logical retained payload, not CLR headers, ONNX model
weights, process RSS or native allocator order. Exact-envelope budget succeeds;
one byte below refuses before the single-use claim and can be retried at
the valid budget.

Seventy injected throw/cancel prefixes cover every observed semantic stage
and every repeated symbol/pending/clone/queue/application/registration/write
boundary in the actual cold fixture. These are library exceptions and
cancellation boundaries, not emulations of every native helper's false status,
allocator refusal or ignored DOM-mutator return. Native branches which still
allocate MATH_NODE after an earlier helper failure remain static evidence;
this batch does not claim their complete allocator-failure equivalence.
No failed target can be read as a completed result or retried. Its prefix,
including applied nodes, counter advancement and cached IDs, remains visible
to diagnostics; cleanup runs once without fabricated whole-operation rollback.

## Verification and limits

`LegacyMathFreshPublisher.Probe` runs genuine official Microsoft CPU ORT1.23.2
using the fingerprinted Math bundle. Six actual outputs comprise cold width1
and its physical reversal, plus explicitly PREPARED search widths3/16 and
their reversals. Wider searches evaluate actual NN outputs with the actual
field bound before NN; they are not proof that a fresh native EEB selects
width3/16 automatically. The production entry stays cold width1. The sole
additional old RawOnlySource seam is a named diagnostic factory forwarding
the same existing private core with a prepared width and actual field.

All first-copy rows are processed in these fixtures; none uses a shorter
fallback candidate. An empty row VECTOR is explicitly outside this positive
three-insertion scope and is refused before claim. Empty-alternative/range
branches must not be advertised as additional real NN captures when these
six outputs do not produce them. Four separate E-only point/repeated-point
experiments produced nonempty output, so no genuine empty-vector test is
claimed. No expected transcription is supplied to recognition.

The independent Python oracle reconstructs raw features/source order,
positions/C79/C21 unions, raw AL intervals, all typed candidate and temporary
nodes, every range string, pending/registered IDs/counters, all cloned
subtree origins, three ordered patch actions and each failure prefix. Feature
error is0 on the tested host. Concurrent factory controls prove one winner,
GC proves the detached publisher does not retain the disposed NN source, and
the source-backed output remains the positive retention control. Disposing
the publisher leaves its borrowed first-copy pool live.

Managed and Native AOT captures are identical on the test host. The oracle
also passes with isolated Python, an external working directory, ten tracked
helper files and NO research directory. Fresh old Managed/Native captures
for source positions, first-copy, outer-copy, full EE4 and original-field
source retain their previous hashes. Hashes are same-host evidence, not
universal cross-CPU floating-point goldens.
