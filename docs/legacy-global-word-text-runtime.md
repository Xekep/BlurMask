# Bounded global CHAR → WORD/TEXT publication

This batch adds a native-order parent around the real fresh global CHAR wrapper.
It does not adopt an old configured-two-alternative owner or finish the document,
coverage, detached DOM, acceptance or recognition-quality routes.

Only two existing files change: `LegacyFreshMainGlobalTextSourceWrapper.cs`
(typed parent reservation and ordered child hooks), and
`LegacyOwnedMainTextSourceInterner.cs` (typed global WORD sidecar). The AVL
numerical body is unchanged after removing its new constructor sidecar argument.
Existing standalone global choices and CHAR publication retain exact captures.

The parent retains the exact original completion, scope, pre-NN INPUT document,
Seed, shared words/characters/selections/string pool and actual source guides.
Its original WORD collection, ordinary CHAR union and NULL-projected full INPUT
TEXT collection remain separate. MIR and II really have unequal WORD/TEXT
coverage: aggregation can complete, but subsequent coverage needs the missing
238B0 geometric branch. No interval AVL is presented as that geometric owner.

The parent reserves the underlying Choices entrypoint before WORD mutation.
Direct Choices publication therefore refuses in the interval before CHAR entry.
The child validates that claim rather than claiming it again. Every entered
failure poisons parent, wrapper and Choices, including cancellation before any
WORD/CHAR prefix. A deterministic internal barrier checks this interval with a
foreign scope on the same immutable document; production exposes no callbacks.

The native sequence allocates the zeroed document choice32 first, interns the
original WORD key, initializes WORD defaults and its zeroed choice48, then enters
the CHAR wrapper. All references refresh before per-glyph selection, processing,
interning and emission. Positive source visits clear WORD bit21 before refresh;
selected CHAR row flags accumulate into the WORD choice. WORD registration uses
the original WORD key, then creates document WORD link24, appends actual source
lines56, and registers NULL-projected TEXT. Native failure prefixes and consumed
selection counters remain visible. Line allocation refusal still advances the
wrapper offset without inventing published lines.

Whole-stage preflight bounds 4096 links, 65536 alternative rows, 1048576 projected
ranges, 256 INPUT objects and 4096 guide lines. Counts use long arithmetic before
claim. Cached WORD references/storage, active compact storage and every selected
owner's full pool bytes are checked again before claim. Live source/WORD changes
refuse without mutation, then a restored input can publish.

The 4-byte-per-row bound applies to admitted ordinary scalar rows, not arbitrary
emitter inputs. Every available primary AL token and virtual fallback is checked
against the actual normalization data. Canonical scratch containing an ordered
F0000/F0001 writeback pair refuses before claim. Without a replacement pair the
existing completion returns original UTF8; smiley replacement is at most four
bytes and 021000 classifies/interns the exact interval. Matching compact entries
must resolve to ordinary nonexternal, nonmacrocontrol emission. Other token
variants refuse explicitly.

Validation uses 13 actual global sources (four procedural and nine committed
recorded tracks), full CHAR records, source positions/ranges, selected flags,
WORD/TEXT command memberships, native scalar24/48/32 and guides56. The independent
Python oracle first checks the paired CHAR producer against raw model bytes,
then independently recomputes parent flags, source memberships, line geometry,
counter changes and every failure prefix. It does not receive expected labels.
Thirteen prepared failure branches, two reservation interleavings, two live-state
preclaim controls, five budget controls and 1024 degenerate-range predicate
controls are separately labelled. Prepared skip and reuse predicates do not
constitute natural recognition coverage. Natural duplicate/reuse owners remain
zero in this corpus. Managed and NativeAOT outputs must match byte for byte.

The numerical oracle is portable without research/vendor code: its four Python
files read models and captures only. Static proof scripts separately read vendor
bytes/decompilation; they never execute or load an SDK DLL. Russian baseline
quality is unchanged; this batch does not finish Russian joined handwriting or
claim an entire recovered engine.
