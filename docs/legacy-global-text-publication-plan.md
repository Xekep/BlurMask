# Same-global source to pre-NN document publication

This is a read-only checkpoint and proposed owning join. There are no runtime,
app, model, dictionary or golden changes. A global raw result and the detached
post-import byte result are different lifecycles; neither is accepted text.

## Live source versus imported bytes

Native normal getter00F460 first calls controller.V80=2271F0 at00F65B. After
success it unconditionally calls TOP273.V68=13E7F0 at00F6A5. V68 visits each
span, invokes219580 if packed10 bit2000 is clear, marks that bit even on the
callback failure path, then requires13D360 ranking and13D000 checkbox handling.
The genuine no-candidate branch still requires source export and275.V08 score
publication. A null external argument does not remove this stage.

The live2DA.V18=0283B0 path obtains wrapper.TOP10, then TOP8's actual frontend.
It reads frontend250/source218, uses the original TOP48 glyph pool, refreshes
owners through217670/13A830 and emits glyphs through0213A0 using its live
primary alphabet.024F30 builds actual CHAR alternatives/positions and the
WORD source choice vectors;021AB0 reads assigned source guides through218.V100.
It is not a concatenation of a completed byte string.

The separate136B40 path sets wrapper20=1, imports through TOP.V30, capturesV38,
clears TOP8/10 and releases the source wrapper. Its later05BAC0 byte emitter
selects dynamicTOP18 as primary. The imported2A IDs cannot be passed through
the acoustic AL or substituted into liveDocument glyph selection. The portable
import intentionally retains a distinct copied pool and validates unchanged
original pool/WORD snapshots. A subsequent live217670 refresh or V68 WORD-score
mutation would invalidate that snapshot correctly.

Consequently the next live publication must branch from the completed **raw**
global callback result before control import. It can share the existing actual
first-alternative capture, quote cleanup and freshF4 return, followed by V68 and
live source publication. The current `LegacyFreshMainGlobalPublishedCompletion`
continues to represent the detached imported byte route. It is not silently
replayed, mutated after import or redefined as a Document result.

## One selected-input binding before NN

The shared selected owner is line_geometry's
`LegacyLibrarySelectedInputBinding`: its old and OriginalSelected variants
retain their real concrete input, Document, registry ID, Next, C22 ranges and
DAF input rows. The original selected branch uses the actual
`LegacyLibraryOriginalSelectedFieldContext`; it is not converted into the old
one-INPUT context. No second C22/binding implementation is proposed here.

The existing configured publication route creates/imports2C1/2DA/shared3E and
the Seed before `models.PrepareConfiguredDocument(sameDocument)`. Its new
OriginalSelected variant is separately frozen for root review. The global sister route
must have that same ordering and exact binding:

1. Validate the actual completed OriginalSelected owner and retain its binding.
2. Create the processing context, input-only2DA import, live result lease,
   shared3E/CHAR/WORD trees and Seed.
3. Prepare the global invocation with that **same Document**, without creating
   an equal-looking second raw document or replacing the pre-NN Seed.
4. Run actual global graph/context/cache/controller/final publication/callbacks.
5. Bind the actual global TOP once; retain source/selection/session leases.
6. Perform the live source-completion and source-rich publication stages below.

Current `PrepareGlobal(raw,...)` constructs a fresh raw Document internally.
It therefore needs an additive internal `PrepareGlobalDocument` sister to
`PrepareConfiguredDocument`, sharing a private prepare core. The old public raw
entry retains its document-creation behavior and numerical captures.

`LegacyMainSharedTextSourceState.TopOwner` currently has a concrete old owner,
and its PublicationScope lifetime is concrete too. A later approved narrow
internal typed binding/lifetime core can retain old or global ownership, with
strict old getters. It must not manufacture a configured alternative, source
graph, candidate, registry ID or old TOP just to satisfy a signature.

## Smallest actual global source-completion scope

The first bounded candidate is the actual fresh global one-alternative,
one-WORD, one ordinary descriptor/no-pending-metadata source, with every active
compact row's bit8 clear. These are owner checks, not public caller flags.

An E-only read-only diagnostic on the verified4a533ec+frozen14 library observed
all nine recorded tracks in that domain:22,440 full compact records, zero bit8
rows, one ordinary descriptor and zero pending/context records for each source.
All868 existing NN evaluations remain unchanged through inspection. Expected
labels were not read. This establishes a reachable bounded branch, not V68
completion or improved handwriting quality.

Native219580 calls frontend188 twice, count then fill, with mode2 and an exact
26*N allocation (24*N references followed by2*N residual bytes). Forward1A9AE0
differs from mode0 at its explicit mode2 trailing-control block: that block needs
final-node pending208 and nonFFFF metadata. The proposed restricted owner must
derive their absence from the fresh actual source lifecycle. Pending/reverse
and custom metadata branches remain refused until separately ported.

The current `LegacyFreshMainGlobalSourceRanges` owns real shared-graph span0 DFS,
selector order, original key records and chronology. It is the right source for
the bounded forward count/fill adapter. A glyph-range union or independent
SingleLine sampler is not an equivalent WORD source. The span key and WORD
clipping ranges must remain distinct. The E diagnostic's existing mode0 output
is labeled as such; it is not presented as a produced mode2/V68 owner.

A new typed global source owner can then reuse the existing numerical ranking,
275 score-finalizer and absent-RU-checkbox proof. Even singleton ranking must
execute its real policy and update the actual WORD120/279 references. No public
`completed=true` or no-op score callback is acceptable. Other WORDs/alternatives,
active bit8 augmentation and pending protocol inputs must refuse rather than
be omitted to obtain a result.

## Following source-rich joins

Existing configured source wrappers are deliberately strict: two alternatives,
one shared span, one concrete graph and actual275 payload views. They cannot be
enabled for global sources by changing2 to1 or casting a GlobalResult.

After the source owner above, the minimal useful sequence is:

| Stage | Actual global owners and reusable kernels | Remaining work |
| --- | --- | --- |
| Ordinary217670 refresh | final compact2470/2478, live global pool, GlobalGlyphSourceMetadata/overlay, GlobalGlyphScoring/confidence | owning global refresh adapter; preserve exact written-field/query order and failed-prefix/single-use behavior |
| Glyph alternatives and CHAR | actual refreshed owner +13A830 marker selection +13A0B0/default helper +0213A0/021000 | global live emitter, same3E, primary AL/empty live2A/empty alternate ownership, actual source position projection |
| WORD source choices | actual span source26N/clip, all actual275 payloads, selected279 ordinal | global typed payload view,024F30 new/reuse CHAR interning, WORD48/ref24/TEXT32 publication without reconstructing text |
| Source lines/TEXT | original descriptor-to-guide assignment and pre-deskew guideC/10 or corrected14/18, source rotation0 proof | same global source218 projection through021AB0; native append/write counters, actual TEXT selection and line/source postprocessors |

The initial ordinary/no-pending scope may cover the nine short recordings but
is not a reason to discard global higher/protocol rows or to claim general
multiline publication. The actual graph/overlay/source range identity must be
retained at every stage. Main descriptor IDs, line IDs, graph context IDs, raw
object IDs and C51 selection IDs remain distinct domains.

After that bridge, existing library document/DOM/BE2 transport kernels can be
adapted through the same input binding, with their real transform/selection/
counter/replay guards. Native05F720 request/history receiver ownership is still
a different boundary; a private library DOM apply is not C20 acceptance.

## Scores are not an application threshold

Keep candidate24.field0, symbol confidence vector10[88], owner1C, glyph0C,
glyph14 geometry/class cost, WORD120 costs and normalized TOP mass as separate
source-bound channels. In particular a singleton normalized alternative mass
can equal1 by construction; it is not a calibrated probability of correctness.
No `.85` acceptance score or `TextRecognition.Confidence` mapping is proved by
this checkpoint. Raw/library source publication should not decide UI acceptance.

## Proposed isolated implementation order

The first runtime proposal is a **new global pre-NN publication scope and bounded
actual global WORD-source/V68 owner**, with only the agreed internal model /
Document / lifetime seams. Then add ordinary refresh and source-rich CHAR/WORD
publication in a separate batch. No app adapter/default change is included.

Tests must retain genuine raw inputs and same model/cache/Document objects,
reject foreign equal-looking sources and stale spans/pools/bindings, preserve
explicit allocation residues and failure prefixes, and compare old configured
and global captures. A selected INPUT tag different from a raw object ordinal,
multiple copied registry IDs and a before-NN2DA identity are required controls.
Prepared branch/cancel controls remain separate from observed native inputs.

`audit_global_text_publication_plan.py REPORT [REACHABILITY]` composes native
result/source lifecycle, imported-byte detach and2C1/input construction audits,
then checks five additional split-code regions,34 instruction pins and six
bindings. It never executes vendor code. The E-only reachability capture is
optional and is not a new runtime API or an accuracy oracle.
