# Global024F30 source-wrapper checkpoint

This is static evidence and a proposed next implementation boundary. No source
wrapper runtime, CHAR registration or accepted transcription is added here.
The completed glyph-choice stage remains unchanged at this checkpoint.

## Native order and distinct source operands

024F30 has two loops. In its first loop it resolves the current actual WORD
reference and reads that reference's descriptor **immediately before that
reference's own refresh**. A kind1 run is skipped only when its masked7FFC
length is nonzero and its low two bits equal3. Scalar kind0 equal to the actual
AL's U+200D label marks the special-joiner branch. Neither fact can be inferred
from recognized strings after refresh. Capturing all descriptors before the
loop would incorrectly assume earlier refreshes cannot affect a repeated owner.

Every eligible source is refreshed and projected before any selection. For an
ordinary source its projected C21 ranges are intersected with the actual WORD
source key: at025259..025265 the RHS pointer/count come from024F30.param5+20/+28.
The library's corresponding source is the successful global completion's
`CopyRanges()`: it already derives actual26N count/fill references from the same
global graph source and actual WORD span, then projects them into the same
original Document. Passing the whole raw root or treating span integers as raw
point endpoints would change this operand.

The degenerate-source containment test uses a **different** RHS:024F30 takes
`local78=param3[2]`, then passes that full original source collection's+20/+28
to Contains118.05F050 populates this collection by copying the selected input
source at+40. This is not the WORD clip. In the bounded library raw route the
full collection is represented by the original closed root range generated
from the exact Document's original selected-input map. The future factory must
validate it against the exact bound selected INPUT ranges and pre-NN imported
2DA ranges; only the fresh full-domain case is admitted. This is an explicit
library adaptation for the verified full-domain scope, **not** a general native
identity between an INPUT C22 and collection118. Foreign owner, partial domain,
cached/C25 and external collection cases must refuse.

The second loop interleaves the following for each eligible WORD reference:

1. Actual13A830 selection with its original signed marker.
2. Ordered source processing: degenerate-outside-full-domain downgrade to
   mode4; special U+200D conversion to a terminal-normalized insertion; otherwise
   the first eligible later-source overlap decides which source loses points.
   It does not subtract all later overlaps. Existing shared
   `LegacyPreparedMainTextSourceProcessing.Process` already implements this
   numeric lifecycle with actual same-Document range operations.
3. Exact01B4E0 interning in the same invocation's CHAR interner. Ordered unsigned
   first/last pairs and count form the key. No sorting, coalescing or geometric
   approximation is introduced.
4. New key:0213A0 followed by024D40. Existing key:021760 over the retained payload.
   Emitting all glyphs first and consuming their results later would break this
   native order, failure prefixes and duplicate-source reuse.

021760's existing numeric loop must remain unchanged: its original row-count
snapshot bounds lookup, interning occurs before matching, and failed publication
can retain a zeroed/appended row and updated marker. Reuse does not run the fresh
smiley/filter/empty-removal caller again.

## Typed ownership and proposed narrow seams

A NEW sealed processed-global-source receipt must retain the exact wrapper,
global scope, completion, WORD/reference index, successful selected-glyph receipt,
V140 owner, projected/processed ranges, actual WORD clip, full-domain receipt,
Document, shared3E, Seed and pending-selection context. Its ordinary status is
produced by the actual source-processing kernel. No public constructor, positive
flag, prepared-node import or Document-only equivalence may substitute for it.

The future wrapper binds `scope.SharedState.Characters`, `.Selections`,
`.Strings` and `.DocumentSeed`. The same Seed must remain the context's bound
publication seed, the same StringPool must belong to both Seed and context, and
the selected input binding must be identical. The new wrapper may keep a typed
global payload dictionary; the existing dictionary of old count1/configured
payloads must not be coerced into holding global objects.

The following **five class seams** are proposed for review before any edits:

1. `LegacyFreshMainGlobalTextGlyphChoices.cs`: internal typed publication claim,
   completed first-pass receipt, per-reference selection, fresh emission and
   entered-fault notification. Mechanically refactor its existing public
   `Publish` onto the same helpers and retain every current output. Wrapper mode
   is bound by a sealed same-owner wrapper receipt, not a caller success flag.
2. `LegacyFreshMainGlobalGlyphDocumentPositions.cs`: read-only copy of its one
   cached full-domain root interval, validated against the bound selected/imported
   ranges. Existing exact projection and shared-map lifetime remain unchanged.
3. `LegacyOwnedMainTextSourceInterner.cs`: named actual-global-processed entry,
   with a separate explicit typed global-source sidecar on a new node. It must
   require the receipt's exact scope interner, not just equal Document/range
   bytes. Existing old `FirstSourcePositions` and old processed-source getters
   remain strict. Numeric AVL/comparison and old outputs remain unchanged.
4. NEW `LegacyOwnedFreshTextSourceContext.Global.cs` partial: a named validated
   actual-global CHAR registration entry calls the existing privateCreateCore
   with kind0. It checks exact scope.Selections/InputBinding/Seed and an actual
   ordinary processed receipt. Production must not call `CreatePrepared`.
   The old selection file requires no edits.
5. `LegacyPreparedMainTextGlyphReuse.cs`: a named internal global factory and
   actual-global Apply entry bind the exact global emitter/shared3E and genuine
   existing payload. The existing private Process numeric loop remains verbatim.
   The old public Emission getter and old public Apply stay typed and strict;
   no old result/alphabet owner is fabricated for a global invocation.

These are four existing files plus one NEW partial file; no other existing
class/API expansion is included. Internal provenance receipts may be added as
new files. Source-processing numeric kernels and Document range operations
already exist and need no changes.

## Scope and verification required before integration

The proposed initial runtime remains one actual forward ordinary WORD with
fresh full-domain selected input, no pending/associated/C25 sources and the
same global pre-NN scope/3E/Seed. The subsequent
[payload-metadata closure](legacy-global-text-payload-metadata-plan.md) traces
SourceLineId, scalar defaults, prior-state traversal and computed flags through
their actual producers, including native failure-prefix distinctions. It does
not assign zero or borrow a count1 sampler. Runtime is still unimplemented at
this static checkpoint. WORD/TEXT source registration, transforms,
transport/acceptance and the application recognizer switch remain later stages.

Existing13-source Managed/Native choice captures must remain byte-identical.
New checks must reconstruct actual WORD-clip operands and full-domain operands
independently, verify per-glyph source/selection/interner/emission trace order,
typed source provenance, C21 exact keys/tree/insertion order, actual duplicate-key
reuse and pending CHAR prefix. Prepared skip/joiner/degenerate/overlap cases must
remain separately labelled. All nine committed Russian tracks must be attempted
without expected text entering inference; bounded refusals and quality remain
separate diagnostics. Failed prefixes must retain native mutations and poison
retry without accepted output or implicit rollback.
