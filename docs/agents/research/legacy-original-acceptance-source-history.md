# Original receiver after selected document publication

The original-selected library document now has real original PAGE/field/INPUT
provenance and a retained selected C20/C22, pre-NN2DA/3E and actual result C4D.
Its successful library registry replay and kind4 DOM apply do not supply the
remaining CBB receiver. This read-only checkpoint identifies concrete missing
owners and a smaller source-history operation suitable for the next port.
No runtime or frozen document13 files change here.

## Original source application and rollback are distinct algorithms

Original C20.V188 dispatches C4D.service38=Ink07E210 because original58 is
nonnull. The method begins the history lifetime on that original C4D. A failed
begin returns false before application. After a successful begin it requires
the C4D's exact F8 source target, sets recording108=1, and calls078090 with
the incoming transaction+8 and cloneSelections=true. It keeps recording108=1
after that call even when execution failed, ends the begun history scope, and
returns the saved execution status. The selected clone's history-disabled
direct078090 branch omits these required original objects.

Original observer0797F0/079A10 creates the history command record around the
actual registration operation. Its record is a forward operation4 with the
original-target C22 clone, name/category and returned ID. It is not valid to
rename the incoming result C4D as this generated history frame. Allocation,
recording mode, observer ordering and completed registration determine which
history commands actually exist.

The before observer's history-allocation failure is not an executor refusal.
Original C20.VE0=06BE30 calls the forward before loop0653D0 at06C020. That
loop invokes observer90 at065450 and immediately advances to the next observer
at065453; it checks no returned status.06BE30 then executes C51.registration38
at06C0D1 and calls the reverse after loop065480 at06C100.0797F0's failure
cleanup clears frame110/tail118 and returns void.079A10 later exits if that
frame is missing. Registration may therefore succeed while the generated
history is absent. This differs from failure to clone the incoming temporary
C22 inside078090 before VE0 is invoked. A library implementation must expose
the actual execution outcome and generated-journal completeness separately;
it cannot treat the observer's allocation failure as an atomic refusal of VE0.

The reverse walker is C4D.primary.V18=077570, whereas the forward generic
executor is078090.077570 requires F8, disables recording108, starts from the
frame's tail pointer10 and walks command.previous10. Its real opcode4 branch
calls original C20.VE8=069630 to delete the exact registered ID. Its opcode7
branch reads C51.Max through service18, not C51.Next. It only invokes the
Next setter28 with oldCounter20 when Max is below that old counter. The code
sets recording108=1 on successful completion; early refusal preserves the
entered failure prefix instead of unconditionally restoring that flag.

This has an observable consequence: undoing newly added selections does not
justify restoring the complete original counter bytes. A generated history
frame may contain only operation4 records, because the incoming trailing
operation7 is skipped once explicit-ID registration has already advanced
Next. Removing those IDs can leave Next monotonically advanced. A synthetic
"restore initial Next" shortcut would differ from the native transaction.

For the proposed source-only branch the required exemption is a checked

## Smallest next data-producing scope

The useful next original operation is a library-owned **original source
command application with its generated journal and inverse traversal**, not
another compatibility checksum and not a public CBB facade. Its actual inputs
already exist: the same completed original bootstrap/chosen original field,
its selected publication document, the successfully transferred same-source
C4D and the independently checked original raw domain. It would apply the
actual category100 operation4/7 sequence to an active original C51 view,

The proposed library adaptation below must be reviewed before runtime. The

### Explicit library Base70 adaptation and lifetime

The Engine global28 service operates on each actual Base70 object passed as
param2. Its native parent60, transaction stack48/count50, current frame58,
listenersD0 and recursive parent commit/rollback are not supplied by the
library bootstrap. The proposed owner therefore does not expose a native A8,
C4D pointer, C81 handle or CBB receiver. It is named a **library original
source history**, with one retained source journal, one library parent-frame
identity and one application frame. A one-depth library manager records
begin/end and an explicit inverse traversal over this frame; it does not
claim to implement the general native history service or page listeners.

The intended construction and consumption contract is:

1. `LegacyLibraryOriginalSourceHistory.Prepare(actualOriginal)` requires the
   successful unchanged bootstrap and retains its exact Document,
   CurrentView, complete initial registry/C22 identities, source events and
   original journal snapshot. A narrow bootstrap claim retains this history
   owner; a second history owner for that original is refused. The historical
   `Original.State` is unchanged. Current registry state is a separately
   named immutable `ActiveState` snapshot of this retained owner.
2. `history.CreateSelectedInput(actualOriginalEntry)` constructs the existing
   original-selected context from that exact original and registers its
   identity with the history owner **before** pre-NN scope construction.
   The supported first version issues one such context. Application rejects
   a previously constructed unrelated selected context, even with matching
   ranges. It never substitutes the Seed or a generated INPUT tag after
   recognition. Existing public bootstrap/selected APIs retain their behavior.
3. `history.PrepareApplication(actualDocument, actualOriginalCompatibility)`
   claims the actual successfully transferred pending C4D on the exact
   document receipt, same scope/binding, issued selected context and chosen
   original entry. It validates complete original/selected registry equality,
   actual requested IDs and category100, raw range bounds, no auxiliaries and
   all-ID/total-range budgets before cloning. The real original preflight
   must be ready and compatible; a claimed DOM scratch preflight must also
   succeed. No caller command list or success boolean is accepted. The
   original-target C22 clones belong to this history's original source domain,
   not the worker-selected replay's target identity.
4. `application.Run()` enters the library parent/source frame, then executes
   the actual forward4/7 sequence in native command order. Each new4 prepares
   the original observer's name/C22/category record before registration and,
   when that preparation succeeds, finishes it with the actual returned ID,
   preserving generated previous/
   next order. Equal registry C22 values can share the original-domain value;
   the history's prepared range clone remains a distinct retained value.
   The incoming transaction and generated history keep separate identities.
   An internal prepared observer-history allocation refusal still proceeds
   through actual registration; it records that actual active-state prefix
   and execution outcome, with incomplete/unsafe generated history. It does
   not invent a native false result or a complete inverse for the new ID.
   Trailing7 can skip after explicit adds advance Next; only callbacks that
   actually occur can generate a history row. Native07E210 ends a successfully
   begun lifetime even when execution returns false; it does not implicitly
   reverse the frame. The library owner retains the same failure prefix.
5. The document retains this claimed application/result identity. A claimed
   pending, failed, unsafe-history or rolled-back original-source application blocks explicit
   library target apply. An unclaimed old route keeps its old behavior.
   Worker-selected registry replay remains separately named and does not
   substitute for original-source execution. Neither success changes CBB
   revision fields nor claims original DOM/page acceptance.
6. `application.Rollback()` is explicit and allowed before any library target
   apply, using the generated frame rather than the incoming commands. It
   follows tail/previous order, suppresses recursive original C4D recording,
   deletes each actual generated4 ID and applies the exact Max/oldCounter rule
   if an actual generated7 exists. Next need not return to its original value.
   It retains the CB7 source event/clear trace under the proved no-match domain.
   It refuses a second rollback or an unsafe postwrite failure; no inferred
   original DOM inverse operation is added.

The lock order is document receipt, then history/application, then its private
registry/frame data; construction before a receipt does not call back into a
document while holding the history lock. The history owns its managed data,
not the borrowed document/scope. Closing it invalidates new live history
operations without disposing those borrowed owners. Live application checks
also validate the document's existing scope lifetime. Detached scalar/range/
journal snapshots survive close; they confer no authority to apply again.
Only one original/selected/application generation is supported, so a second
selection cannot silently read the historical bootstrap after active mutation.

Managed registry containers and retained typed identities are a documented
library representation, not fabricated native AVL/hash/pointer storage.
Deterministic logical release of staged range clones and frames replaces
native handle release; it must never dispose borrowed C22/source owners.
Preentry cancellation leaves the claim reusable. Entered **executor temporary
C22** clone refusal or command-boundary cancellation retains the completed
active-registry and generated-journal prefix, ends the library frame and
poisons forward retry. This does not describe an ignored observer allocation
refusal: that can leave a newly registered ID without its generated inverse.
An explicit rollback is permitted only when that prefix has a complete
generated inverse. A postwrite recording failure or partially failed09F380
cannot be labeled atomic, retried or reset to an initial counter. Such a
prefix is retained and marked unsafe; the first runtime need not expose a
prepared simulation of every native allocation failure. Named internal fault
controls must distinguish executor prewrite clone failure, ignored observer
history refusal and postwrite structural inconsistency. A positive execution
status with incomplete history is retained as such, not silently promoted to
a safe application result.

This would be genuine new data production on the original source. It still
