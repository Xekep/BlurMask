## Actual ownership and ordering

Native238B0 calls2DB.V18=050660 with retained Ink, actual result2DA,
original-range mode1 and geometry mode1. This happens BEFORE01FD40/020000.
The proposed input therefore is the COMPLETE genuine global WORD/TEXT parent,
its actual publication/Seed/retained original Ink, and a cropped owner whose
Publication is that SAME parent. The later global selected overlay is not an
admissible substitute: it changes source flags and already refuses MIR/II.
No configured2 adaptation, fake node, synthetic rectangle, source interval AVL
or existing2DB owner can supply this input.

The original050660 sequence is:

1. Reserve WORD64 rows from chosen document32 WORD24 links; preserve actual
   chosen WORD48 identity, chosen index, selection ID and CHAR link order.
2. Reserve CHAR80 rows and concatenate selected UTF8 bytes with the original
   selected-row byte-count andC00 gates. Initialize CHAR time extrema only to
   native LONG_MAX/LONG_MIN; these sentinels are not computed timing results.
3. Derive native line memberships and retain actual result F8 guide pointers.
4. Sum retained guide+18 double angles in line order; mean first, cos and sin
   second. This is not a mean inferred from stroke slopes or bounding boxes.
5.04B4C0 performs vertical geometry, calling04AA60 moments as needed.
6.04E480 performs horizontal geometry, including04D2C0 and ordered04E0E0
   CHAR metadata mutation. Both helpers are mandatory for geometry success.
7. Only after both succeed, derive global horizontal extrema and WORD time
   extrema from the actual computed CHAR extrema.

Failure may leave the preceding native prefix written. The final nonempty
050660 path clears+b0 even when a numerical helper returns failure; this byte
alone is not a Ready predicate. Empty result returns separately. A new owner
must publish Ready only after its complete admitted operation succeeds.

## Vertical and horizontal numerical contracts

For the initial one ordinary WORD entirely in one source line,04B4C0 uses the
actual WORD original range. Its ranges are not the full TEXT key. Eligible
CHAR iteration is a separate branch when the WORD/line/special gates require
it. Raw resolution is the exact same retained original C20 and original-range
mode1; mode0 actual Ink.V128 registry lookup remains distinct.

04AA60 reads genuine cropped points in source/range order. C49/C4A direct
access and C4B chunks of at most20 are distinct dispatch paths, already proven
by merged cropped views. With previously computed double cos/sin:

```
Xrot = float(double(Y)*sin + double(X)*cos)
Yrot = float(double(Y)*cos - double(X)*sin)
```

Extrema use the native ordered float comparisons; N/sumY/sumY² are double
moments in exact native point order. No midpoint, bbox or point-dedup shortcut.
Mean/std, retained guide baseline/height and2.5/1.5 extensions follow04B4C0.
Neighbor-line04A680 is not naturally reached by this single-line corpus.

The selected400 special branch can WRITE the referenced F8 guide baseline.
It is absent on all37 actual selected rows, but a general producer must either
reject it before claiming or record that precise mutation and failure prefix.
04E0E0 may OR02000000 into actual CHAR metadata when its class1000/width
predicate holds, BEFORE later04DA20/04DD50 can fail. Actual13 has no selected
class1000; do not claim the mutation is unreachable for arbitrary input.
CHAR10000 half-height is naturally present on II and requires explicit support.

04E480 scratch64 +00/+04 are integer group indices, including -1 sentinels.
Decompiler `-NAN` spellings in those lanes are not floating-point NaN values.
Only exact instruction operands may determine branch/assignment types. Its
ordinary scratch+24/+28 fields are conditionally assigned, not universal zero.
The final horizontal producer needs the full proven04C340/04C440/04D2C0/
04DA20/04DD50/04E0E0 closure, including native mutation/failure ordering.

## Newly exposed timing boundary

CHAR80+40/+48 and WORD64+30/+38 aggregate source.V50-derived signed64
values. They are not raw object IDs, sample ordinals, X coordinates or geometry
widths. The newly pinned lineage is:

* C49 runtimeE65B0.V50=08E030 reads object+30. Constructor08DDB0 copies its
  FIFTH argument to+30. Kind0 factory090CF0 forwards its fifth argument; it
  does not supply a zero default at this boundary.
* C49.V18=08E040 invokes the format's actual instance V38 with original raw
  storage, point index and that baseTag. Descriptor/metadataE6FD0+08 points to
  instance tableE70C0; E70C0.V38=0984E0. Confusing metadata tables with actual
  instance tables produced exploratory wrong slots;0983A0,096D90,071300 are
  explicitly excluded from the evidence set for the timing reader.
* C1C ctor0978D0 reads FLOAT rate from descriptor+10, computes float32
  `1_000_000/rate + .5`, then CVTTSS2SI to format+28. This is not a hard-coded
  sampler default. It scans actual channel ID4 and preserves its converted
  unit multiplier; XY-only has no channel4 and sets format+30=-1.
* Reader0984E0: no time channel means signed32(format+28)*unsigned32(index)
  +signed64(baseTag). With time channel it loads the actual signed32 channel,
  multiplies signed32(format+2c), then adds baseTag. Native32-bit channel
  addressing arithmetic and signed conversion must be checked before bounds.
* C4A.V50=08E960 delegates original base.V18 at its stored first point.
  C4B.V50=08F350 interpolates two original base.V18 values at the fractional
  first point, double arithmetic plus .5 then signed64 conversion. It does not
  interpolate the already-rotated geometry or raw source identity.

The fresh textField/addItems INPUT proof registers and copies an already
constructed C20/raw root. It proves INPUT tag/registry semantics, not a new
C49 ctor baseTag or C1C samplerate. Ink065940 likewise retains an incoming raw
object; it does not establish fresh raw-object timing defaults for that input.
The current library InkPoint has XY only and explicitly omitted unused timing
properties. The native constructors CAN accept two different rates/baseTags
for identical XY. The audit includes a symbolic non-uniqueness check, clearly
separate from a native numerical oracle.

An upstream public/fresh raw ingestion API could impose actual constructor
defaults. That CALLER lineage is still pending; absence is not proved merely
because the current library omits timing. Before a full producer, prove that
specific admitted caller and add a NEW typed constructor receipt carrying the
exact rate/channel/baseTag semantics. A receipt must be created by the proved
constructor branch, not a caller boolean asserting "default timing". Do not
invent zero/baseTag or synthesize time from RawObjectIndex meanwhile.
