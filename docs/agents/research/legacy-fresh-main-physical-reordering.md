# Fresh direct main physical reorder

`LegacyFreshMainPhysicalReordering.Prepare` consumes the owned15B260 descriptor
snapshot and executes the following15F050 branch of the **fresh direct source**.
It accepts neither prepared provider groups nor arbitrary guide/flag/carry values.
It retains current descriptor ownership and original physical/point identities.
The only extra inputs are the two exact committed portable2E3 model resources.

## Source E8 scope and intermediate passes

`163970` initializes source219's E0 and E8 pointers to null. The explicit external
metadata setter `163F50` is one machine instruction storing R8 to source+E8;
metadata219 table`2DF0A0` slot28 points to it. `1680D0` invokes E8 slot18 only when
that pointer is nonnull. The input owner's API is specifically fresh direct
source construction with no external metadata setters, property events, previous
source or page guides. Its E8 callback is therefore genuinely absent; an arbitrary
SDK source or loaded249 child whose owner installs a callback is not that scope.
This does not invent a guide or pretend to recover a general callback binding.

`161120`'s merge branch requires source descriptor20=`02000002`. The fresh split
snapshot has20=`?1`, so that branch is inactive. `15EAA0` leaves the physical order
unchanged when every boundary18 is?1, as in this untouched direct source. Direction
bits have the fresh ordinary value cleared by `15D360`. The source has no existing
strings/source720 records at this pre-first249 stage.

## Per-descriptor receiver state

The first15B260 grouping phase supplies the initial neural scale. For each ordinary
split descriptor with two or more physical strokes, native15F050 resets the2E3
provider through `076AD0`, supplies that descriptor's current retained points,
then executes the unknown-line slot50 branch. Reset clears point/group/prior
containers, but leaves runtime190 and scale-active byte12 intact. It does not call
provider slot38 again. Its actual grouping result is produced with the carried
positive scale; internal samples above nine can replace it. The next descriptor
receives the resulting scale. A one-physical descriptor bypasses the grouping
call and leaves that carry unchanged.

Slot38 (`077120`) stores its primary XMM2 argument to runtime190 and sets12=1.
The secondary XMM3 argument supplied by15B260 is ignored by this setter. No
secondary-scale assignment is inferred from the native caller's signature.

A local numeric receiver view reuses the existing verified grouping arithmetic.
Its current point arrays are compared against the parent retained buffers;
preparation is **rejected** if a second source ingress filter would change any
point. This is a checked implementation restriction rather than a silent extra
filter. That view's metadata/probabilities are not exported as the parent source.
The final source probabilities and original keys are copied/permuted exclusively
from the actual parent snapshot. A later direct receiver implementation can remove
that restriction without changing the established ownership contract.

The exact interval consumer sorts returned IDs within each provider group, uses
source primary scale (not the receiver's carried/re-estimated scale) for the
float-tolerance/double-gap expression, and preserves native overlap insertion.
`16AA00` then composes the existing factor200 map through the physical permutation.
Descriptors retain their current24/28 ranges and all other published bytes;
separator kind3 rows are skipped, never treated as physical strokes.

## Verification and remaining boundaries

44 independent actual-model NumPy controls pass in Managed and fresh Windows
NativeAOT:75 provider calls,1453 original retained keys,6 changed interval orders
and24 real receiver-scale changes. Different-height rows force the carried scale
to change; printed equal-height fixtures alone would not establish that property.
Every resulting physical order, provider-call scalar/count, descriptor byte and
factor200 map is checked. The optional pinned PE-only audit verifies13 constructor,
setter, reset, scale-active, intermediate-pass and interval bindings. No vendor
DLL or GUI is executed.

This restores one owning fresh **direct** source ingress branch up to the
postprocessor boundary. It does not infer an SDK/loaded249 E8 override, select a
first or main word winner, run the six postprocessors or supply live font x-height.
Those caller bindings and selected-result/guide lifecycles remain separate. It
also explicitly rejects retained inputs on which the temporary numeric view would
introduce another source filter, instead of claiming all numeric edge cases done.
