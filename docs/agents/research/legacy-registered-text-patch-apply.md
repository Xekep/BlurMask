remaining owner boundary. It does not relabel library DOM/cache transfer as
native C20 acceptance.

## Concrete receiver boundary

create the backing page ink and DOM through its retained store. Both inner38
(Ink/C20) and inner30 (DOM) must then exist. The method returns those actual
owners. It cannot be supplied by a fresh library kind4 BCC root whose V200 is
null or by an unrelated selected INPUT/C22 object.

CBB.V110 is115800. It consumes those same inner38/30 owners, page/history CB7 at

Its native row loop first checks before-version matching, invokes source
Ink.V180 and DOM.V210, then source Ink.V188 with the actual C4D when required,
then DOM.V218 with the actual edit and range/mapping output. It has real
rollback/history outcomes, not an unconditional success callback. C81's

CB7 and actual bindings; constructor-null fields do not prove their final
absence. CBB11AF60 retains that existing inner/page owner and registers its
wrapper with CB7. This still does not prove that every native input request's
reader.V200 is CBB; that binding is a caller prerequisite.

The library's fresh selected INPUT context has proved C20/C51/C22 ownership,
but it intentionally does not own this C81/CBB page/store/revision lifecycle.
Its ORIGINAL fresh C20 constructor is history-enabled (063EC0 ->0638A0 with

the selected copy's history policy.

## Smallest possible next runtime and its dependencies

The actual pending-C4D operation4/operation7 subset has useful, bounded native
semantics in078090. Operation4 clones its retained C22 onto the target C20,
preserves the requested selection ID/name/category and verifies the returned
ID when no remap table is supplied. Operation7 validates both counters are
nonnegative and calls C20.VF8 only when current Next is below the requested
new counter. After explicit-ID operation4 registrations, Next may already
equal that counter; operation7 is not an unconditional setter.

A future owning registry replay can consume the actual pending transaction and
the same worker-selected INPUT/C22, deriving the disabled-history policy from
this exact caller/clone lineage. No global history-manager callback belongs to
that branch. A coherent runtime still needs the actual C51 registration/update
producer and its immutable state transport, preserving the previous INPUT
snapshot and source provenance. Before it can be native C8E patch application,
the C81/CBB reader/page-store factory, source-name and revision producers plus
CB7 must be restored. Public caller booleans, a fresh empty target and supplied
revisions are not those producers. No new acceptance runtime or public API is
introduced by this checkpoint.

## Library snapshot retention

The publication document's tree content and byte copies are immutable. The
existing tree snapshot type retains Arena -> Seed -> Scope, so it is not an
owner-free value: retaining a tree can retain immutable model owners. Scope
finalization cannot close a still-reachable scope. Deterministic Scope.Dispose
is the lifetime contract; it releases strings/request bindings even while
those immutable tree snapshots survive. A future additive owner-free tree
value can strip these provenance references without altering native transport.

`audit_registered_text_patch_apply.py` checks the two full PE hashes, exact
virtual bindings and ordered native instructions. It never executes a vendor
DLL. Existing runtime7 and its captures remain unchanged.
