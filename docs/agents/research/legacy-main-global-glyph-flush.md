# Global numeric glyph flush planning

`LegacyFreshMainGlobalGlyphFlushPlan.Prepare(actualGlobalBacktrack)` joins the
actual selected global compact path to ordinary21FFD0 flush packets. It retains
that pass's post-final-V80 result lease, exact cumulative path costs, winner
channels, graph boundaries and source70 owner. A shared numerical kernel also
serves the existing CASE/configured flush planner; typed owner checks remain in
the adapters.

Every flush exposes real72-byte append rows, the64-byte packet write template,
residual additions and initial WORD120 seed origins. Seed-dependent bytes are
explicit dependencies, not zero-valued native metadata. This planner does not
supply the initial WORD seed, run callbacks, associate residuals or declare a
successful WORD publication. A protocol flush containing a row is not evidence
that source1A0 emitted a printable delimiter.

The eight genuine global paths produce two flushes each. The probe repeats64
stack residues per owner:512 complete plans,1,024 flush packets,1,984 full72-byte
rows and32,768 separate integer-wrap/F32 arithmetic controls. Independent raw
compact/graph reconstruction verifies every packet byte, seed origin, flush
boundary, visited index and padding byte. Acoustic evaluations do not change.
Managed and fresh Windows Native AOT captures match SHA256
`882ce606a12a25404621208c013a97bbdc6f302103f04ff6b00cdc21af5ed322`.
Existing CASE flush and owned WORD-seed/residual callback probes pass in Managed
and rebuilt Native AOT with their previous complete captures unchanged.

All these actual global compact paths have terminal identity+24hex equal-1;
there are zero source70 metadata events. The new post-result source70 lease is
required for the general consumer, but these inputs do not exercise its guarded
metadata call. Separate metadata controls must state their prepared-consumer
scope. Native packet seed, callback failure, nonordinary/end branches and
complete global218560/WORD/document publication remain separate work. This is
not an accuracy benchmark or a complete21FFD0 port.
