# English119 rich result to source720: static proof and proposed bounded owner

This package is static evidence and a runtime proposal only. No new EN source720 runtime has been implemented or integrated. It does not establish full English recognition accuracy, main-source processing, native TOP273 serialization or application recognition.

## Actual producing join

The selected EN lite owner already produces a genuine rich glyph pool and ordered WORD120 objects: `LegacyEnglish119PlainTextResult.Factory`, `.Storage` and `.NativeWords`. Every WORD is verified against the same private pool. Its factory retains its actual terminal, candidates, preparation, graph source ranges and policy categories. The next join can use these semantic data producers without manufacturing a serialized TOP273 or TOP18. Native TOP18 control2A is not the acoustic AL and must not be substituted with it.

`156950` reads the first alternative at TOP273+68 and follows the WORD chain (node+20). It walks every WORD's reading-order references, obtains signed node24/arc16/alternative16 fields, skips negative arcs, and obtains the actual nested glyph owner through TOP273+48's pool service08. The selected alternative contributes label+8, confidence+C, confidence+10 and cost+14. Selected confidence is pow(binary32 confidence, binary32 driver+1C8), converted back to binary32. Other unique alternatives are appended up to twenty, with unpowered confidence channels. It does not obtain labels from TOP18 or an expected output string.

The frontend at driver+1F8 supplies candidate begin/end through V168/V170 and actual source ranges through V188, with mode0. The callback chain is pinned: frontend168/170/188 -> graphB8/C0/120; the actual candidate source-range owner is `LegacyOrdinaryGraphSourceRanges` with its retained cut chronology and original source. `012BC0` applies the submitted child-to-parent physical map before `157030`/`157340` source geometry. Categories originate at the same selected source130 sampler: graph initialization `1A6980` resolves sourceV88 -> samplerV70 -> graph+188; frontendV48 forwards that exact category storage. The EN policy already calls its actual sampler108 `ReadCategories(token)`; the old `LegacySourceSamplerCategoryOwner.ReadV10dSource` is deliberately unsuitable. No widening or coercion of the old RU wrapper is proposed.

The pure shared `LegacyFirstResultSourceRecord.Create` already implements these scalar/range/geometry kernels. The proposed EN join will feed it actual owned glyph alternatives, selected signed ordinal, resolved source ranges, exact pre-NN submitted buffers/map, actual policy categories and the loaded selected249 exponent. It will traverse all actual ordered WORDs, including delimiter WORD references (negative arcs skipped); it will not reinterpret the result as the old single RU WORD type.

## Missing input ownership and proposed receipt

`Preparation.CopyOriginalStrokes()` returns deduplicated input. Source ranges resolve raw-before-dedup point ordinals, including the ending raw index of a duplicate run. Near-equal dropped coordinates cannot be reconstructed from retained points. Therefore accepting arbitrary parent buffers after recognition, or taking deduplicated copies, would break source geometry/ownership.

Propose NEW `LegacyEnglish119SourceSubmission` with a constructor/factory that receives the actual selected `LegacyFirstAcoustic119WireModel` and raw child input, validates all aggregate bounds before allocation, defensively copies exact binary32 coordinates, creates identity physical map0..N-1, and itself constructs the existing `LegacyOwnedEnglishLiteFullPreprocessing.Prepare(model, exactCopiedRaw, token)`. Its public Preparation enables the existing candidates -> policy -> terminal -> rich result pipeline. The final materializer must require reference identity of result.Factory.Preparation with this receipt's actual Preparation and the same retained model/source/selected processor; equal hashes or separately prepared buffers are insufficient. No caller labels, category owner, exponent, map or supplied result cells are accepted.

Propose NEW immutable `LegacyEnglish119SourceRecords` output containing ordered source720 records plus explicit source WORD/reference provenance snapshots. An internal new materializer validates the same candidate graph, source ranges/prepared chronology, original source and actual pool; snapshots each WORD's references once; resolves each nonnegative arc via that actual source-range owner; reads selected owner alternatives from the actual pool; and calls the shared pure Create. The result contains defensive snapshots and typed retained ownership. It makes no native pointer/ABI, document application or main-source append claim. It is safe to have zero rows when all actual WORD references are delimiters; do not manufacture a label to force a row.

Bounds before copies: raw input1..256 strokes, each1..4096 points and **4096 aggregate raw points** (existing ingress cap), finite coordinates; no unbounded resource copy beyond the existing64MiB model cap. Validate cancellation during every input/WORD/reference/range/point loop. Whole-stage at most4096 reading-order references and4096 published rows,65536 resolved ranges,1,048,576 geometry point visits; a single pure row's4096 projected-fragment cap must also be preflighted before allocation. These are portable library work limits, not native format maxima. Snapshot refs once and retain raw input once; avoid rescanning/copying the entire PAGE/model/raw input for every row. Reject unsupported source/category/graph branches rather than coercing them.

## Native filtered-parent boundary explicitly excluded

The first proposed receipt is **direct-child input with identity physical map**, and returns source720 in that exact submitted-child coordinate space. This is a useful semantic producing join, but is not a recovered native157C60 parent submission. The real EN parent is coordinateMode2 with early processors and later physical reordering; the actual current parent buffers and secondary+B0 scale are not yet owned by the EN first pipeline. Borrowing a RU frame, guessing scale from line height, or falsely declaring descriptorkind6 would invent that missing state.

Native157C60's ordinarykind0 filter uses parent secondary+B0 double: binary32 width >3*that double and binary32(height/width) promoted to double <.02. It retains the final stroke if otherwise no stroke is submitted; kind6 bypasses the filter. Its callback receives exact parent-retained floats and records their actual physical indices in the map. `SelectChildPhysicalIndices` alone is not the complete lifecycle.

There is an additional important native sole-flat path. The flag for an originally single flat stroke leads to `156E80` on the last published720 row after156950 and before157340. `156200` resolves a one-byte charset1 literal from DAT_1802E9BAC, which is **underscore (`5F`)**, using the actual nested source's AL, storing its label at driver+1E8. If that ID is notFFFF,156E80 writes that label, confidence1, second confidence1, cost0, and missing alternatives. A future native filtered-parent owner must retain/prove the exact AL lookup and this override, plus descriptor34/38 append interval, child close and failure reset. The initial direct-child scope neither invokes this native parent policy nor claims equivalent native157C60 full output.
