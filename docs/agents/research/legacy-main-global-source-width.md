# Global source width and glyph packet scalars

`LegacyFreshMainGlobalSourceWidthStatistics.Prepare(plan, geometry)` binds the
actual global compact/backtrack/flush owners to the same live source geometry.
It produces the no-associated `TOP273.AC=2` and the `TOP273.B0` width mean used
by the glyph protocol caller. It validates the current result-query lease before
and after the prepass. It does not evaluate the four acoustic networks again.

The internal numeric kernel is shared with the existing single-source width
owner; its public API and prepared numeric controls retain their behavior.
Within each genuine flush, native `2188F0` scans the 72-byte rows backwards,
uses the actual compact subtype and marker filters, reads the original live
group bounds, subtracts X coordinates as float, and adds that width as double.
`221840` initializes sum/count to zero. A positive signed count produces the
float conversion of the double mean; a nonpositive count explicitly writes
zero to `TOP.B0` at `2219DA`. These fields belong to TOP273, not WORD276/120.
`227776` derives integer `AC=2` from the no-associated source branch, and the
first `221840` invocation has null WORD/publisher arguments at `2277B9`.

The new probe records eight actual raw-input owners, their compact bytes,
native flush rows and live bounds, then supplies the derived scalars to the
real ordinary/protocol producers. The independent Python oracle recomputes
the ordered float/double accumulator and checks `request64+2C/+30` against the
derived values. The probe additionally exports the SAME selected compact
record, per-node2478 starts and authenticated raw5134-byte acoustic alphabet.
The oracle walks compact predecessor/alternative references independently,
uses raw alphabet marker/joiner/unit labels and native normalization, and
requires all eligible records to match the complete flush membership and
chronology. It derives ordinary/protocol counts from those raw compact records,
rather than requiring a historical selected-winner row count. The current trace
contains22 ordinary rows and eight FFFA rows; the former23-ordinary trace
predated the corrected actual2B1 feature producer. The source-assigned FFFA
delimiter emits no label. Six corrupted captures must be refused, including
coordinated row/producer/bounds deletion and permutation. All prior float/double,
packet, scratch, width-diversity and source-owner checks remain. These are input
fixtures, not expected-text or recognition-quality tests. Their global controller is
still partial: the reachable `2144F0 ->213C00` soft-hyphen join is a separate
pending integration. These traces are not a complete native winner claim.

Label scratch and WORD allocation remain separate requirements. `2173E0`
initializes a cursor to 256 but leaves the 256 labels as stack residue; the
probe supplies an explicit nonzero label pattern. The protocol request's
64-byte residue is also an explicitly prepared test buffer. Future WORD
construction must supply the actual 120-byte allocator residue: `13F110`
does not initialize bytes `44..53`. This width owner does not manufacture a
WORD seed, pool, glyph source references, publication callback, or final text.
The eight actual traces have no source70 metadata events; negative pending
cursors remain covered by the separate protocol controls.

Verification uses `LegacyMainGlobalSourceWidth.Probe` with the standard nine
global probe arguments (AK, engine profile, separation, case, publication,
line30, line50, output capture, LK), followed by its `audit_output.py`.
`audit_main_global_source_width.py report.json` checks pinned PE instructions
and the existing width, publication and WORD-seed static audits. Vendor code
is never loaded or executed. The old `LegacyMainSourceWidth.Probe` and its
independent 256-segment oracle remain regression gates.
