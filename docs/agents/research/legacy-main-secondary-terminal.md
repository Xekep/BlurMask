# Actual secondary matrix terminal selection and exclusions

`LegacyOwnedMainSecondaryTerminalCursor` connects a successful configured CASE
pass's owned2410 matrix to native2257C0's multiple-secondary selection branch.
It requires the private before-construction `0x012D0003=2` provenance, the same
model/controller/graph/session, and the existing no-associated/nontracing,
EC0/no-rescue source policy. A caller cannot supply replacement rows, context
IDs or a manufactured second entry to this owning entrypoint.

The cursor reads the complete actual final88/2410 allocations and preserves
SourceEnd23F0 rather than RetainedEnd23F8 as its scan extent. Matrix entries are
indexed by `(storedOrdinal*2404+secondaryOrdinal)*40`. The outer stored88 cost
and flag27 still gate the entire block; a finite matrix entry does not override
an impossible outer row. Each block stops at its first impossible00 cost, even
when a later allocated entry happens to contain a finite value.

The numerical scanner retains native strict comparison/tie order, source
language penalty, signed32 overflow and filter/fallback predicates. The
multi-secondary24B8 predicate is distinct from the previous single-secondary
helper: only a root context with labelFFF9/FFFB/FFFC bypasses inspection. The
same labels at nonroot contexts do not bypass it. Both reusable paths retain
their separate native conditions.

A successful selection appends the selected40-byte entry's opaque mapped
identity08 to the exclusion vector. It does not compare labels, decoded text,
279 object pointers or raw context10. The actual source-row count bounds the
native exclusion allocation. The selected raw compact-index field comes from
40.1C, and not from88.22. The output retains copied selected88 and40 bytes plus
their actual pass/source owner; none is exposed as a restored compact index or
recognized text.

`SelectNext` owns only this2257C0 exclusion state. It does not drive2271F0's
accepted-output counter, impose a fake successful publication, or decide how
duplicates affect that counter. `ConfiguredOutputLimit` is therefore kept
separate from the cursor's number of possible terminal requests. A later273
controller must stop or repeat selection using its actual callback outcomes.
No rescue body is invoked or synthesized. Existing count1 result and compact
consumers remain unchanged and still refuse configured2 input.

The cursor validates the completed source query lease on preparation and each
read. An external node/epoch refresh makes it stale; it does not create another
backend, reset the dictionary or rebuild a parallel DIRECT owner. Entry
cancellation preserves the unconsumed cursor. No-winner/source-budget exhaustion
terminates it, and a subsequent read is rejected. Returned record arrays and
exclusions are copies.

secondary entries and no finite per-row second entry. Its different first
identities nevertheless yield16 distinct numerical terminal choices through
actual exclusions. The first two are genuine next terminals on that inference
storage. These16 choices are not16 published alternatives or texts; native
configuration still limits ordinary accepted output to2.

An independent Python scan reconstructs the entire choice sequence, signed
cost/cumulative values, raw40.1C and all2,048 selected88/40 bytes. A separate
original generator supplies512 prepared matrix cases for root/child controls,
strict ties, first-impossible termination, identity exclusions, all source

owning guards cover cancellation, exhausted/stale leases and repeated use.
Expected handwriting labels are never read or used to steer inference.
Managed and Windows Native AOT captures are byte-identical.

The static auditor checks four pinned PE regions and instruction pins for
matrix00/04 reads, root checks, strict comparisons, identity08 exclusion tests
