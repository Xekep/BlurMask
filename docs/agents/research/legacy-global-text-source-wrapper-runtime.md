# Bounded global CHAR source wrapper

`LegacyFreshMainGlobalTextSourceWrapper` joins the already completed global
TOP.V68, actual ordinary V140 source metadata and the original document to
024F30 source processing, exact C21 interning and fresh CHAR payloads. It
does not register WORD/TEXT, accept a document result or change the app default.

The wrapper retains the original global scope, pre-NN shared3E string pool,
Seed, INPUT binding and pending CHAR transaction. It admits one ordinary source
descriptor with no known-text inputs or negative protocol references. Its
complete original root must equal both the actual INPUT range and imported
2DA input range. The actual WORD clip is a separate RHS. Unsupported variants
refuse the operation; no sampled legacy/count1 owner is manufactured.

The first pass reads each current descriptor immediately before its own
refresh, then projects the real source indices and clips against the WORD.
Every eligible reference finishes this pass before any selection. Repeated
references are not deduplicated or reordered. The second pass selects,
processes ranges, interns the exact ordered key and immediately performs either
fresh213A0 plus024D40 or same-wrapper21760 reuse. The existing native numeric
reuse body is unchanged. A prepared/old interner node cannot be relabelled as
a global payload; the CHAR interner must be empty when the wrapper is claimed.

The new processed receipt carries the actual same-owner selection and V140
producer. Fresh metadata registers CHAR using the existing private command
kernel. Its cursor comes from the actual selected INPUT registry. SourceLineId
comes from the actual acoustic group, its descriptor ordinal and descriptor88
field+10, plus the native per-alternative offset initialized to zero. The prior
byte starts at1 and clears on each fresh C4A row visit: an empty traversal is
distinct from an ordinary positive traversal. Unwritten native fields remain
nullable; the written mask exposes a genuine failed-registration prefix rather
than fabricating zeros. Entered failures poison the wrapper without rollback.

Only four existing files change: global choices (narrow internal orchestration,
old public Publish body unchanged), cached original projector (root copy),
source interner (typed global receipt sidecar), and glyph reuse (typed global
adapter, numeric Process body unchanged). The selection join is a NEW partial
file and calls the original private CreateCore. Runtime files and validation
are isolated from the app's default recognition route.

Validation on the four procedural inputs and all nine committed genuine
Russian tracks passes Managed and NativeAOT, with byte-identical captures:
`3d35ab40e01c1fcc6356163d7438cf81b06ad0b16b2562f5f9dbddaccd9c6006`.
This is13 sources,37 processed keys,80 full40-byte UTF8 records and115 guards.
The independent Python oracle checks original packed positions, WORD clip,
source processing, unsigned exact keys/AVL/insertion order, UTF8 classification
and identities, all assigned payload scalars, prior visit counts, actual source
LineId joins, CHAR commands and precise refresh/selection/publication order.
It also runs with Python `-I` from a three-script portable directory with no
research files. Expected labels never enter inference or the algorithm oracle.

leave SelectionId/flags unwritten and append no command. These controls do not
claim genuine OCR coverage of those branches or four distinct managed heaps.

The actual13 corpus contains no source-key duplicates or overlap branches.
Same-wrapper reuse is implemented through the unchanged separately proved
