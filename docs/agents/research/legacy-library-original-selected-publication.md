# Original selected INPUT publication before NN

The additive `LegacyLibraryTextPublicationScope.PrepareConfiguredOriginalSelected`
entrypoint accepts a completed `LegacyLibraryOriginalSelectedFieldContext`.
The source owner is never coerced into the older one-INPUT0 context. Its exact
original bootstrap, CurrentView, immutable raw Document, chosen field/tag,
complete copied C51 registry and child-owned C22 remain retained.

The ordered join is:

1. `Context.CreateForOriginalSelected` creates a new library2C1/result2DA and
   result-owned strings3E. It retains the exact selected owner through an
   internal discriminated binding.
2. `PrepareInput` reads a same-document managed reader facade of the actual
   selected PAGE/field/input snapshot, imports the chosen input.tag and C22
   ranges, and finishes the proved input-only02D8C0/054340 branch with flags1.
3. The publication scope retains its context lease and constructs the shared
   CHAR/WORD state and Seed against that same binding/result/strings3E.
   source30 is the actual chosen registry ID, constructor UUID38 is zero,
   initial TEXTD8 is zero, and the retained108 vector owner already exists.
4. Only then does `models.PrepareConfiguredDocument(context.Document,...)`
   prepare the existing configured2 raw/NN pipeline. The resulting TOP is
   bound once before document WORD/CHAR publication; UUID initialization occurs
   at the existing publication boundary. No Seed is replaced after inference.

This is a library-owned configured2 route. It does not claim the full049370
resource scheduler, original CBB/page history/revision ownership, SDK acceptance
or a global multi-line adapter. The chosen original field's native C98 kind0
and namespace come from its sealed producer. No caller no-history/success
flags are added.

## Complete registry and source identities

The test's original has two actual fields, `left` and `right`, with INPUT IDs0
and1 and Next2. Either choice keeps BOTH selected C51 entries. The chosen tag
is0 or1; 2DA.source30 and Seed.source30 retain that exact value. New pending

The internal `LegacyLibrarySelectedInputBinding` retains either the old exact

and named factories provide the union; callers cannot construct it or supply
registry IDs. Result input binding, Seed, shared pending transaction and WORD

OriginalSelectedInput/OriginalSelectedInputContext properties; old concrete
SelectedInput, BoundInput28, Seed.Input and WORD SelectedInputContext getters
throw on this route. Old public factory signatures and old-path values stay
unchanged.

The processing reader facade copies actual selected node/value/child metadata
and retains the authoritative selected owner. It is an explicit managed view,
not a second native00C590 clone, a new original context, or another C20.
Internal kind2 lanes retain the actual empty-prefix/page-URI pair separately
from normal attributes. Its local name-index table belongs to the facade;

Existing public DOM snapshot shape is preserved. The new probe reads the

## Lifetime and supported boundary

Context.Dispose immediately closes new context entry. A live publication
scope retains result bindings, reader facade and strings until its final lease
is released. WORD disposal does not dispose borrowed strings. Scope.Dispose
closes live Seed/WORD validation, disposes the context and releases that lease.
Already copied scalar/range/UTF8/tree bytes remain immutable. The independent
selected bootstrap owner is borrowed, so scope disposal does not steal or
invalidate its external ownership.

Preentry cancellation remains reusable. Entered NN failure poisons the scope.
The new importer also exercises explicit prepared refusal/cancellation prefixes:
reset/tag-binding/range-import order is retained and context flags are cleared
on failure. A failed context cannot be prepared again. These are named test
service boundaries, not invented native cancellation callbacks.

The new route currently ends after real document CHAR/WORD/TEXT/source cleanup.
`PublicationDocument.Prepare` explicitly refuses it BEFORE its ownership CWT
claim. `DocumentInputTransforms.ApplyCore` refuses it BEFORE the transform CWT
claim or vector swap. The tests require NotSupportedException twice, then
continue the still-valid source/TEXT path and verify the initial vector owner
is unchanged. A late invalid-old-getter exception would fail these controls.
The old no-new-route document path keeps its existing transform/transport/
replay behavior. A dedicated same-original adapter is still required for the
new registry replay/compatibility/transform/transport continuation; no caller
success boolean or page/history facade substitutes for it.
