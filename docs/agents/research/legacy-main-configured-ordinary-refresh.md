# Configured ordinary glyph refresh

The named `LegacyOwnedMainOrdinaryGlyphRefresh.PrepareConfigured` entry uses
the actual completed candidate-source view, selected session overlay and shared
TOP glyph pool. It scans the genuine configured compact storage, appends or
updates native descriptors, applies the actual symbol resolver and acoustic
scoring, and invokes the existing finite glyph-alternative selector. It does not
construct a historical count1 RawResult to access those kernels.

Each cached refresh is keyed by the actual configured alternative object. A
cache hit also verifies the identical overlay and result-publisher ownership,
checks the resource fingerprint and validates all256 separation-table values.
Two sibling alternatives share the source invocation/TOP but do not share this
mutable refresh state. SourceIdentity alone is intentionally not a cache key.

`LegacyOwnedRussianMainGlyphScoring.PrepareConfigured` binds the actual exporter,
candidate and overlay to the existing numerical cache. Its NN/geometry/cost
arithmetic is unchanged. The old scoring and refresh entrypoints keep their
count1 scope; RawResult explicitly throws on the new variant. Historical
interrupted-prefix claiming before source export is preserved.

The configured refresh currently supports base ordinary source owners only.
It explicitly refuses a higher source before changing the pool or claiming a
partial refresh. The actual configured captures have zero residual sources;
they do not prove a shared native higher-arc namespace across alternatives.
Functional per-session overlay support and numeric higher-source scoring do
not establish that missing cross-alternative join. Span refresh, UTF8 emission,
TextGlyphChoices and TextSourceWrapper are not widened by this batch.

The new headless probe runs actual raw preprocessing and configured inference,
then refreshes the two real selected candidate owners. Both Managed and Windows
NativeAOT visit four marked compact rows, add two glyph rows and check15 guards.
An independent oracle checks all320 pool bytes, request fields, finite selection
order and the actual selected marker (including a nonzero input marker).
Scoring values remain outputs from the separately audited acoustic/scoring
kernel; this composition oracle is not a second neural-network implementation.

A separate prepared guard, after the actual captures, uses genuine base ranges
to create a functional-overlay higher source. Both refresh attempts refuse it
without pool mutation. It is not an inferred residual, a shared-overlay test or
a positive configured higher refresh. Cache guards also reject changed
resources/table contents, foreign candidate metadata, cancellation and incorrect
variant getters.

The original five-input refresh regression remains unchanged:24 owners,48
compact rows,43 new glyphs, five prepared higher sources and116 guards. Its
independent oracle checks2680 pool bytes and all selected markers. The existing
static auditor pins ten native instructions in217670 and eleven managed stage
ordering points; no vendor DLL is executed.
