# Owned main compact word materialization

`LegacyOwnedMainCompactWordReachability` and `LegacyOwnedMainCompactWordMaterialization`
connect a successful source-owned main pass and its prepublication numeric terminal
selection to genuine compact40 storage (`2460`), per-node starts (`2478`), updated
beam row22 and primary-pool1C indices. They do not produce text or an acceptance
confidence, and do not implement all branches of `207CB0`.

The supported publication route is fresh DIRECT mode 0, primary alternatives 2,
secondary alternatives 1, header count 2, packed source low 3 greater than 1, EC 0 and
no trace/associated source. The complete source graph must fit inside its actual
resource-backed maximum-atom lookahead. Older-prefix publication, CASE V58
expansion, same-node primary alternatives, associated/protocol candidates and
forced-boundary marker alternatives remain explicit refusals. Ordinary beam rows,
empty-context same-node cached-word markers and used-arc candidate headers are
implemented. A header is added for a USED arc: the native bitmap-zero branch
skips it; this is not an unused-arc repair policy.

The reachability stage also accepts longer owned sources. It clears and marks
native beam `byte6.bit1` and `pool1B.bit7`, preserving all remaining full-capacity
storage. Its native lookahead frontier uses graph maximum atoms, not a supplied
glyph length. It retains one `207780` request and its source backend for later
publication queries. The actual 4/56-node reachability controls make no queries in
the first marking phase; the actual 4-node materializer exercises 285 eligibility
checks and 437 backend reads. `207780` inspects output `48+17` hex, the low 3 record kind.

Result-query capture happens after the producing pass's final source V80. Reads
reuse the same dictionary backend and last installed permission map, without a
new D0, backend replacement or invented reset. The source epoch must remain
unchanged; a later pass/map/controller epoch invalidates the result. CASE lease
hooks retain the distinct post-V80 lifecycle but do not widen this DIRECT
materialization scope. Callers must materialize before changing the owning source.

The materializer consumes a private single-use publication lease, including a
failed/canceled publication after entry. Early invalid resources, foreign
confidence owners and pre-cancellation do not consume it. Compact allocator
storage is caller-supplied bounded residue, not a claim about native allocation
contents or ring capacities. Every output getter returns a copy, including the
backing arrays of ReadOnlyMemory snapshots. Bytes22/23 of compact40 records stay
as supplied residue.

Actual `2B7.V58` is `05A3F0` (`xor eax,eax;ret`), so the original primary candidate is
the genuine native fallback. Ordering uses the native middle-pivot quicksort,
group key, raw arc end-context identity, wrapping cost comparison and context
leaf, without generic .NET sorting. Forced deduplication uses context identities,
not string equality. The native 17153 penalty undergoes float multiplication by .8
and signed rounding. Frame production uses owned contexts, exact source category
mapping, the existing `207420/2075E0/206960` stages and `206D30` full 40-byte writer.
Score bytes consume the separately owned `1BE530` candidate field 0 weights:
top 20 exponentiated integer costs, float accumulation and float normalization.
Frontend 150 dispatches `1C1260`, not `1C1300` calibrated channel 0 confidence. They then
undergo float multiplication by 255, truncation and clamping. No expected label
or text is fed into publication.

The genuine 4-node fixture yields 694 records, node starts `[0,50,154,400,694]`
and selected compact index 681. The numeric predecessor path `681 -> 637 -> 636` contains
labels `FFFF,74,FFFA`. These are structural observations, not a successful Russian
text recognition assertion. `21FFD0` glyph/text publication is a separate consumer.

Verification uses the managed and Windows Native AOT probes
`LegacyCompactWordReachability.Probe` and `LegacyMainCompactMaterialization.Probe`.
Their independent Python audits reconstruct native marking and raw-LK query
eligibility, context differences, normalization, ordering, deduplication and
publication. The materialization audit compares all 163,840 compact allocated
bytes and 94,912 beam/pool bytes, including unused residue. The 56-node
reachability audit compares full 1,423,680-byte storage. Static audit
`tools/handwriting/audit_main_compact_materialization.py` pins the vendor PE,
four native ranges, exact marking/query/score instructions and runtime bindings;
it only reads vendor bytes. No vendor DLL is executed.
