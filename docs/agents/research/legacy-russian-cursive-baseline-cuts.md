# Native190350 baseline and loop-exit cuts

`LegacyCursiveBaselineCuts` restores complete prepared-ink stage `180190350`. It receives an explicit baseline, line height and radius parameter. A null baseline selects the native unknown-baseline branch; the native FLT_MAX sentinel is treated identically. No line fitting or handwriting-specific baseline heuristic is introduced.

The stage tracks a pending tag12 and the most recent ordinary anchor. Unassigned points and tags13/14 retain that pending state. An ordinary marker ends it, and the immediately preceding13/14 suppresses cut creation. Tags6/8 use the supplied baseline, the native anchor9 proximity comparison and its14 replacement, and the exact below/above-baseline branches. The below-baseline distance sums segment lengths in reverse point order. The above-baseline branch walks backward until the strict radius crossing and may choose a strict below-baseline point or overwrite a later candidate tag2.

Another tag11 after the pending12 causes an explicit half-arc interpolation and tag2 insertion. The native crossing is strict: an exact arc midpoint at an existing point is crossed by the next segment, which can insert a duplicate coordinate at fraction zero. It uses the recovered prepared-buffer insertion and preceding original-point-map entry. Pending12 followed by rightward tag7 or4 receives tag2 only when the intervening arc exceeds line height. Following marker positions and scan indices advance exactly after insertion.

Russian version106 sampler297 field+1c supplies radius0.35 in both resource nodes. The console probe checks those original bytes. `tools/LegacyCursiveBaseline.Probe/reference_controls.py` creates768 independent own-ink cases with known/unknown baselines, nested marker kinds, both distance orders and varying physical strokes. Of these,137 insert a point. Controls compare every float coordinate/delta/length bit, prepared tag, raw-point provenance and updated stroke count. Additional controls verify the unknown-baseline sentinel, a below-baseline loop exit, strict duplicate-point midpoint insertion, source immutability, malformed metrics and cancellation. Managed and Windows NativeAOT console runs are required before marking the stage ready.

This stage follows loop/horizontal preparation in the native191950 path. The final marker-limit stage191430, override geometry1908c0, full runtime branch selection, line-metric production and ordered candidate/lattice scoring remain separate work. Passing its controls does not establish complete native-engine parity or Russian cursive accuracy.
