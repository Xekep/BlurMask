# Current main first-result line guides

`LegacyFreshMainFirstResultLines` owns the transition from the fresh current main
physical source to each ordinary descriptor's first-child submission, actual
selected first-result source720 publication and24B main guides. It requires the
typed15B260/15F050 result and uses `PrepareOwnedCurrentSource`, preserving original
raw key ownership alongside the current physical order. No first-row frame is
transplanted into the main source.

## First submissions and source720 intervals

Ordinary descriptors are identified by their actual type and current24/28 physical
ranges; intermediate kind3 descriptors are skipped. `157C60`'s existing verified
`SelectChildPhysicalIndices` filters flat strokes using the actual parent's
primary source scale, preserving its last-stroke fallback. This determines the
current increasing child-to-parent map. Original user physical ordinals are not
substituted for current parent indices.

A separate actual first factory receives each descriptor's retained selected
parent buffers and the resource-selected first247 source. Its own model/profile,
frame/cuts/graph and resulting275 record pool retain that factory's identity.
`ApplyFirstResults` requires one genuine selected first word and its genuine graph
range owner for each submission; duplicate, missing and foreign factories are
rejected. The first winner producer remains responsible for supplying those
results, rather than being replaced by fabricated text or geometry.

`LegacyFirstResultSourceMaterializer` resolves the real glyph-pool alternatives
and graph source references against that submission map and current parent buffers.
The first category owner comes from loaded249, so its serialized source exponent
0.75 remains distinct from the raw first factory's constructor exponent1.
`PublishDescriptorInterval` writes actual source34/38 around each append; the
source720 buffer and those descriptor intervals share one owning invocation.

## Main24B guides and geometry

The actual source720 rows are wrapped with the current main controller.24B prepares
C1A items from their real alternative profiles and weights, fits the descriptor's
line and appends its main40-byte guide. `16F170` applies that guide to the
specified physical/row interval and remeasures actual source ranges. Every next
ordinary descriptor receives the already published guide list; descriptors get
actual main10 line IDs. Per-descriptor point outputs are assembled without
resetting a preceding descriptor's transformed physical coordinates.

The result exposes separate published/pre-deskew source720 records and current
post24B rows/points. Original guideC/10 remains distinct from current guide0/4.
The source-key chronology survives those coordinate changes unchanged. Native
ignored temporary-guide bytes are represented with zero portable storage; these
bytes are not presented as computed geometry or a vendor memory bit pattern.

An empty selected first result is explicitly refused because its next main24A
fallback/owner lifecycle is still separate. No whole-word box, guessed height or
first-child guide fills that gap. General24D/29B/265 postprocessing and the final
main-language winner are also not executed by this stage.

line-group NNs, split/reorder, two resource-owned first NN/cache/pruned graphs,
owned regular+blank first primary/context, real selected275/source720 materializers
