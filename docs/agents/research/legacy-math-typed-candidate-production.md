# Older Math: matched-root candidate assembly before 13EC normalization

This static batch traces a genuine matched grammar root into owned typed result objects. It adds an auditor and this description, with no runtime/app changes. It pins 39 complete Ghidra functions/regions, two explicitly labelled exact leaves, 1,199 instruction locations and 38 data bindings. It composes the previous complete actual grammar-serialization proof. Vendor DLLs were never loaded or executed.

There are two different output owners. The grammar creates a **pre-normalization tree** in the input/result worker's base +A0 slot. The actual Math1388 service 13EC later clones that tree, normalizes the clone and caches a **different result** at +168. The first tree is not application-ready merely because its constructors and ranges can be decoded. This batch identifies that second required stage but does not transfer its normalizers or claim publication acceptance.

## Real configured alphabet identity

The existing older 1389 AK resource contains a nested type002B/version0104 alphabet at byte18, after the base-version word. Its payload begins at34 and ends at7171. All 297 terminal-set entries decoded from the actual grammar reduce to 258 unique strings; every one is present in that exact AK alphabet. The report retains every rule/string/actual-label binding. It does not equate label numbers with Unicode or with Math2 EE4 output indexes.

Base grammar setup 026B10 receives the actual AK object and stores its +10 alphabet owner at grammar +18. It then forwards that owner and the actual setup object to applicable child V10/V18 hooks. The derived Math138A setup 047DB0, base1F48 primary table and later 048280 forwarding search wrapper are pinned. This identity matters in 028B10: alphabet V30 is resolved through registered002B primary1DE1B0 to Engine052A80, which appends the actual label's byte string through the retained reverse mapping. A virtual FFFF reverse slot returns success without inventing text. It is not a second recognizer or a parser of raw markup.

The deeper AK inference operators are still open. The base framing contains seven feature/preprocessing objects, a 13F8 object and a final13A4 object before the derived1389 payload continues. Matching all terminal strings against the configured alphabet does not implement those operators.

Its allocation/custom-provider internals are not independently implemented here.

The arguments contain the actual root's name header, selected ordinal and pointers to **two freshly produced range-vector headers**. Name bytes are copied; the range vector buffers become owned through those headers. These inputs are neither arbitrary caller-supplied text nor borrowed copies of a field snapshot.

## Terminal candidates, duplicates and selected ordinal

028B10 populates actual candidate records with stride0x28. Their nested terminal records have stride0x38. It obtains name bytes from the configured alphabet and derives both source range vectors from real matched-node/source data. The full body also handles the actual retained matched-range restriction and the selected alternative; it does not accept an expected label from a test.

028880 compares a newly appended candidate's complete text-byte length/content against earlier candidates. The first equal earlier text wins. The new duplicate's string, nested strings, both nested range buffers and nested-record array are freed, and the new candidate is removed. This is not probability addition, text concatenation or AST-equivalence deduplication. When the duplicate was selected, its ordinal is redirected to the retained candidate.

0280C0 sorts candidate records by descending stored float weight while moving the selected ordinal with swaps. 028B10 then divides weights by their sum when that sum is positive. The native weight transformation function itself remains a separate numerical dependency; normalized stored weights are not calibrated application confidence. No Math2 EE4 confidence is inferred from them.

The base1F44 destructor and storage primitives are supplied by the preceding storage proof. The newly pinned base1F42 destructor releases its name, every retained candidate object, the candidate-pointer array and both range arrays. Base1F43 releases its owned node name, retained child objects and child array. Derived destructors forward to those actual bases.

## Nested candidate construction

028640 constructs each actual nonterminal alternative through VA0, optionally attaches metadata through VA8, appends/retains it in the root alternative array, then calls028240. The actual matched alternative determines selected ordinal; the nesting depth and configured alternative cap restrict which branches are emitted.

028240 walks the matched child references. For each child it creates both real source range vectors, selects V90 for a terminal-root rule or V98 for another nonterminal-root rule, appends/retains the resulting child object and invokes the appropriate fill recursively. The pointers and range headers are produced by that traversal. Optional VB0 stores actual type-dependent metadata through053B90: +60..6C for138D/138E, +38..44 for other node classes. Those fields have not been proved to be a font-size/baseline prediction and are not named as one.

The exact pre-normalization result slot is the base1F40 worker +A0 used by007BB0. Its V40 getter is the explicitly labelled eight-byte leaf003000. No clone or source identity is inferred from matching text strings.

## Both range vectors and fractional source positions

027C00 walks the actual matched bitset over the retained source's node count and calls027980 in source order. It reserves both vectors with real 12-byte range elements. 027980 can coalesce adjacent ranges belonging to the same original stroke when the previous endpoint equals the next start. One vector preserves the source range endpoints; the companion vector converts endpoints through027290 and the actual source mapping.

027290 does more than copy an integer index. It uses cumulative stroke offsets, processed XY points and retained original-point index mapping. Within a plateau that maps multiple processed points to one original index, it sums XY segment lengths and adds the travelled-length fraction to the original relative index. Zero-length plateaus retain the integer position. This is an original-source point-position conversion, not a fabricated timestamp or a font metric.

Consequently an independent raw/current-view owner cannot simply be substituted because its coordinates look similar. A future runtime join must prove the same source identity, cumulative offsets, point-index map, fractional conversion and both vector orders. Existing original source snapshots must remain historical and separate from live application authority.

## 13EC is a distinct normalization boundary

Actual class1388 derives from1F40. Its descriptor09A5F0 points to metadata09A5B8; the metadata callback040940 is the exact service leaf that accepts13EC and returns09A570. That service's +30 is038890. It is an interface on a real worker, not a class named13EC.

038890 returns a cached +168 result when present. Otherwise it gets the base +A0 tree, clones it and, for138E, runs this required ordered chain:

1. 0370A0.
2. 037A60.
3. 037E60.
4. 0386A0 with `identity list`.
5. 0386A0 with `identity vertical pair`.
6. 037680.
7. 0386A0 with `vertical list`.

These are five distinct top-level functions invoked in seven ordered calls. They have their own recursive/table/carry-related helpers. A failure releases the clone and returns zero; success stores the normalized clone at +168. Constructor0342D0 initializes that cache and destructor034430 releases it. The producer's +A0 tree and this clone must retain distinct lifetime and mutation authority.

The top-level owner/dispatch/call order is pinned here to expose the boundary. The full normalizer/helper semantics, cache invalidations and final publication acceptance remain separate analysis. The report explicitly sets `applicationReady=false` and `normalizationTransferred=false`. No direct pre-normalization-to-page shortcut or broad runtime integration is proposed.

## Failure scope and remaining work

Native fills can own partially appended trees before later allocation failure. Some callbacks occur after a child factory or vector growth has already failed; some local range-cleanup paths free buffers without clearing caller headers. Those are not evidence of atomic rollback or safe allocation-failure behavior. An independent owning implementation must preflight budgets, keep exact claimed owner identities and clean its own logical failure prefixes once, while explicitly distinguishing that policy from native bug-for-bug equivalence.

The auditor reads exact vendor bytes, checks every listed body region and binding, then composes the actual grammar child audit and its prior dependencies. It independently resolves all297 grammar terminal-set entries to the actual258 AK strings. This is static/data evidence, not a vendor-execution candidate oracle or proof of recognition quality.

Run `python -I tools/handwriting/audit_math_legacy_typed_candidate_production.py REPORT.json --native-repo SDK_REPOSITORY`.

Still open are actual CBD worker/request creation and source admission, full AK learned operators, node matching/scoring, numerical candidate-weight details, the cloned normalized result stage and original-page publication acceptance. No raw EE4-to-older-search bridge, ready app switch, native font model, Russian completion or whole engine completion is claimed.
