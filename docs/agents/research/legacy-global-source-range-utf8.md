# Actual global source-coordinate strings

`LegacyFreshMainGlobalSourceRangeUtf8.Prepare` consumes the actual completed
global counter handoff. It formats the actual retained CHAR insertion list,
the original WORD key and the actual TEXT key, in that order. It retains typed
references to those same source payloads. No older configured-two-alternative
owner is constructed or substituted.

The pure `LegacyNativeSourceRangeUtf8` implementation is shared unchanged with
the separately checked older path. The existing native formatter audit pins
C21.V180/083DF0, its canonical check/union and decimal endpoint writer, plus
Text0309C0/030EF0/031880's caller operations. This new component does not claim
to implement the rest of031880, node construction, a registry replay or accepted
document. In particular, the counter handoff's operation4 and operation7 commands
remain pending after formatting.

Raw WORD keys are preserved even when canonical WORD coverage has merged adjacent
objects. Formatting independently normalizes its private copy using the native
range kernel; source/interner identity never changes. CHAR flags come from the
actual selected-source overlay, WORD flags from completed cleanup, and TEXT
flags are zero. The native bit400000 caller first-bracket rewrite is exposed as
a separate byte string. Source object indices are original input coordinates,
not selection-registry IDs.

The immutable output copies its keys and bytes on public access and validates
the actual handoff's lifetime and command prefix before returning its entry list
or copying keys and bytes. Identity and scalar metadata remain snapshots. Disposal,
failed parents or changed state cannot turn an old result into current authority.
Cancellation or formatting refusal publishes no result and changes no source,
flag, command, counter, transform or journal. Repeating this pure preparation
from the same valid handoff is allowed.

The first TEXT-key copy is bounded by the existing publication's projected-range
budget. Before copying CHAR/WORD keys or allocating output buffers, the new
component preflights the complete source inventory: at most4096 CHAR entries,
65536 total ranges, and16777216 cumulative squared canonicalization work units.
All endpoint source/point/fraction domains must match the retained raw document.
The conservative output/copy allowance is256 bytes per range plus256 per source;
it is a logical budget, not an RSS or cumulative-GC-allocation measurement. The
unchanged range kernel keeps its own operator bounds. There is no public caller
flag, supplied source class or synthetic fallback result.

The new probe rebuilds the genuine raw13 publication chain, verifies exact typed
identities, defensive arrays, all output cancellation prefixes, stateless retry,
unchanged pending command IDs/counters and disposal invalidation. Its Python
oracle first replays the complete independent raw AL/CHAR and WORD/TEXT
composition checks on the paired same-input child and parent captures, then
joins to their13 original publications. It does not pin one historical winner's
JSON hash. It derives selected/cleanup flags independently, and replays the separate Python
C21/decimal formatter. Expected labels do not enter inference. Managed and
Native AOT output must agree byte-for-byte before integration.

The unsupported actual MIR C25 lookup remains a separate selected-source
dependency. This formatter does not infer an object's native class from its
coordinates, accept MIR through a prepared receipt, or claim completion of the
full text engine.

Four corrupted formatting captures must be rejected: wrong source identity,
wrong normalized UTF8, wrong caller UTF8 and a missing pending command. The
full63-source/13-owner/122-guard fixture coverage and all C21/endpoint checks
remain mandatory. This test-only change leaves inference and runtime untouched.
