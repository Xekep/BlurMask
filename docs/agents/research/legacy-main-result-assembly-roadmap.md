## Cost, mass and rank are different channels

At `2276BD`, native performs signed32 `total-reference` **before** converting
the difference to float at2276C9. The divisor is the signed32 result of
`sourceNodeCount <<13`. Alternative14 separately receives
`float(selectedRowCost14) * 1/8192`. For source kind0x135 the negative normalized
path is multiplied by5 before the inclusive[-75,75] double-exponential/float-store
branch; other source kinds use1. Alternative08 is unnormalised mass at this point.

`LegacyPreparedResultScore` belongs to225FB0. That other path converts its
integer total and signed64 reference independently to float before subtracting.
It cannot silently substitute for2276BD. First-result1F42D0 scoring likewise
belongs to its different merged table, not this main terminal owner. Controls
must include representable integer differences above2^24 where the two cast
orders disagree; a first best-path score of zero would hide the difference.

`13CBA0` keeps raw mass0 while processing later rows backwards. Each later08
becomes `mass_i/(mass_i+raw_mass0)`. Row0 finally uses the denominator from the
immediately following row. A singleton08 becomes1. `LegacyFirstResultScorePublication`
with existingCount0 has this operation and the subsequent0C operation, but its
first-stage name and incremental semantics must not be mistaken for an owning
main result. Main TOP80 is another operation after both channels.

The saved raw first mass is transformed as `mass*.9` when less than1; otherwise
as `1-.1/mass`. Native comparison's unordered path belongs to the latter branch.
The result is combined with old TOP80 through MINSS semantics. Both13B870 and
13BB50 initialize TOP80 to **-1**, so a bridge may not invent a prior value1 or
call the cap an acceptance confidence. The true old field must be transported.

## Minimum owning prerequisites

The current bounded factory already proves one selected source, kind0x135,
mode0, secondary1, EC0, trace2368false, source2300null, caller9Czero, no external
alternate source, stable main graph/cumulative2520 ownership and no rescue bit.
TOP273 allocation and its40-byte alternative vector must be added with the same
pool and source identities. Reference78, raw first mass, row14 and node count
must come from that actual terminal invocation. Source nodes are not letters,
glyph count or caller-chosen prepared atoms: the count comes from controller2310
at22727C, not the selected row's field22. Native279 in-place constructor141540
(metadata2DCC00) clears08qword/10dword/18qword/20qword and sets14 to float maximum;
that constructor and native273.V8 allocation are still an owning join to build,
not an allocator inferred by the numerical row-copy helper.

Fresh configuration99/A8/F4/C4 are live container policies, not model-resource
scalars. The default native container initializes them tozero; a binding must
preserve the fresh/no-property scope. Detailed, associated or property-modified
settings require their real producers and branches. Header/alphabet/control
owners and both opaque four-byte quote scratch slots must retain their exact
identities and lifetime across the whole alternative's linked WORD list.

One small possible ownership adapter is an actual published-word-chain reader
for the existing quote normalizer: traverse `WordPublisher.Head/Next` in native
prepend order and mutate only shared glyph ushort08, without fabricating new
empty WORD builders. It still needs explicit real quote scratch/control owners.
That adapter is proposed here, not implemented by this roadmap.
