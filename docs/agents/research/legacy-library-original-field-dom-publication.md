# Library original FIELD DOM publication

`history.PrepareFieldDom(actualOriginalInput)` retains the original PAGE,
chosen field, INPUT and original name owner **before** history issues its
selected context or recognition runs. This is a named live library overlay;
the original bootstrap State and `field.HistoricalPage` stay immutable.
`field.ActivePage` exposes an immutable snapshot of the overlay.

This restores the bounded original-field algorithms from
`legacy-original-field-dom-join.md`. It does not construct native CBB,
registered source revisions, CB7 listeners, original BE2 history or a combined
native page/source rollback. The ordinary application recognizer/default
engine is unchanged.

## Exact ownership and original child order

The history retains one field owner. `CreateSelectedInput` then requires the
same original INPUT entry; a foreign original sharing the raw Document cannot
substitute for it. The field constructor checks the complete successful
PAGE graph, namespace child, version, content, layout and every original
field/INPUT/id/tag. Field IDs already obey the bootstrap's ASCII
letters/digits/underscore/hyphen restriction. The direct source name is
derived from that actual field ID; callers cannot supply XPath or revisions.

After actual recognition builds and transfers its C4D and result writer,
`field.PreparePublication(document, application)` retains the exact document,
original source application and genuine result payload. This receipt is
also retained by the document. It accepts no supplied edit, recognized text,
target, source name or success flag.

The new field-relative edit has operation2, empty path and ordinal derived
from the actual child scan. Its fresh field already contains INPUT, so this
ordinal is1. The old kind4 library export remains operation2/ordinal0 and
is never relabelled or consumed as this field edit. In the first scope,
prior textResult, activeArea, externally edited fields and replacement
history are rejected. Every other original field and PAGE/layout remains
present and unchanged.

The payload's existing writer has a different name pool. Copies explicitly
re-intern names into the retained original name owner and receive new
library-local node identities. Copied historical nodes retain separate
`OriginalIdentity` provenance. These are typed managed identities, not native
addresses or claimed SDK clone IDs.

## Preflight, source execution and live apply

`publication.Preflight()` clones the **whole kind3 field**, including id,
INPUT/tag and all attributes. It maps the field-relative empty path before
copying and appending the actual result to scratch. The scratch tree is never
published as the original PAGE. Worked, Compatible and entered/faulted status
are separate fields. A claimed field preflight must finish successfully
before `application.Run()` can enter the real original source frame.

`publication.Apply()` requires that exact source application to have succeeded
with complete generated history and no rollback. It builds one ID dictionary
from the active original registry and validates every actual source command's
requested ID, actual ID, category, name, original-domain ranges and command
reference. It also checks all original INPUT entries. This first route supports
only the identity mapping actually produced by these checked registrations.
It neither drops a nonidentity map nor claims native115800's mapping vector
is empty.

Apply maps its parent first, copies the real payload and appends it after
INPUT. It then walks all tagged kind3 elements of the chosen field, requires
signed64/value-kind4 tags, resolves them in that same registry and performs
real C21 range containment against the original INPUT C22. Successful tag
lookup alone is insufficient. Missing IDs, malformed values and ranges
outside INPUT refuse publication.

The independent original-field operation must complete **before** optional
`document.ApplyToLibraryTarget()`. The existing kind4 validation still refuses
operations after that target is applied. Original field and kind4 target
remain distinct graphs, edits and receipts; no old guard is weakened to make
their operation order ambiguous.

The complete original/scratch/two-payload allocation budget is checked before
scratch copying:65536 aggregate retained nodes,32MiB value/name bytes and
depth256 measured from the actual retained PAGE constructor root. The complete
payload bound includes the chosen field's actual parent-chain depth and its
insertion edge, not only depth relative to the field. These are logical bounds on the scoped representation, not process
RSS guarantees. The existing source registry is indexed once per apply;
post-tag validation does not rescan it for every node. Identity-map validation
checks cancellation before entry and for every original and pending selection.

## Failure, lifetime and rollback boundary

Preentry cancellation is reusable. Entered preflight or apply failures are
single-use, retain the completed page/scratch/allocation-count/trace prefix
and leave immutable snapshots readable. Scratch copies and unattached failed
payload copies remain managed-owned until the new lifetime is collected.
This differs from native scratch destruction and is documented storage
adaptation, not a native allocator byte image.

The native BE2 payload-clone-null branch is unchecked. Portable clone refusal
is an explicit faulted library refusal; its Worked=false is not advertised
as a defined native null-clone return. No invented node, success or automatic
rollback is substituted. A prepared postcheck refusal preserves the inserted
result and poisons this lifetime while keeping its page snapshot readable.

Once original DOM apply enters, even before its first mutation, the previous
source-only `application.Rollback()` is blocked. Deleting registered IDs while
leaving inserted result tags would make the DOM inconsistent. A true combined
DOM/source inverse and native page history remain future work. Before DOM
entry, the existing explicit source inverse keeps its previous behavior.

Lock order is document -> source history -> new field DOM -> private graph.
Closing the field owner prevents new field operations; closing history,
document or scope prevents its borrowed live operations. It does not dispose
borrowed owners. Immutable historical and active snapshots remain readable.
Unclaimed old routes preserve their old outputs and behavior.
