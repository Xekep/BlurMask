# Actual original FIELD DOM receiver after source application

This read-only checkpoint follows the original-source application and generated
history. It implements no runtime, changes no old factory and does not claim
native CBB acceptance. It identifies a bounded, data-producing original-field
DOM join and its prerequisites. The current successful kind4 library target
and its exported edit cannot simply be applied to the original field.

## Three concrete differences from the existing library root

Document115800 takes the original inner38 Ink and inner30 DOM, builds an actual
query collector whose output is stack60, and queries the incoming C8F.sourceName28
through DOM.V1E0. It requires exactly one result. It passes that same collected
node to DOM.V210 and DOM.V218. For the supported fresh text field this is the
actual kind3 textField under PAGE/content, not the kind4 constructor root,
selected INPUT node, result UUID or a caller's arbitrary node pointer.

The source-name producer00D0C0 reads the request field's actual kind/name and
`id` attribute, constructing `./page/content/textField[@id="..."]` on the
direct-field branch. The activeArea branch is different and remains outside
the proposed first runtime scope. Its field-state48 revision comes from the
environment's global60 callback. It is separately copied into both caches;
00F110 compares the cache revision with the located field-state48. Neither
successful field lookup nor an equal INPUT tag can replace this check. No
library epoch below is a recovered native revision, and no revision0 is inferred.

Text061510's fresh-source branch scans *all actual parent children*. It tracks
the last matching textResult and its ordinal; if a match exists it queues
removal at that ordinal before new insertion there. If no textResult exists,
0615FF copies the completed child count from R15D into EBP, and06164B supplies
that count to BE2.V60. Therefore a fresh original field already containing its
one INPUT needs insertion ordinal1. The existing fresh kind4 library target
has no child and legitimately exports ordinal0. Reinterpreting that existing
row against the original field would insert textResult before INPUT and violate
the actual producer. Merely preserving all INPUT nodes is insufficient: their
order must also remain correct.

Engine0E2870 distinguishes kind4 from other roots at0E2989/90. For kind4 it
copies each child into a new scratch constructor root. For the actual kind3
field it calls scratch.V88 on the **whole supplied field**, using that clone as
the scratch root. It does not discard the field name, id, attributes or INPUT
before mapping edit paths. All row parents are mapped before simulation.
The separate live0E2D70 maps parents in the same field-relative coordinate
system before mutation. Its insert case clones the payload into the actual
reader, appending when no child exists at the ordinal and inserting before
the actual child otherwise. A successful scratch run is not a live apply.

## Names, mapping and post-application tags are real work

The existing bootstrap retains the original PAGE, every original field and
INPUT, the original name-owner tokens and complete historical registry. The
document's detached writer/target instead owns a different library name pool.
Equal strings, Seed or raw Document do not make these two name owners identical.
A new library field operation must explicitly copy/re-intern the actual writer
payload into the retained original name owner. Its resulting node identities
must be new typed identities; no native pointer or preexisting constructor ID
can be fabricated. Historical bootstrap nodes remain immutable. An active DOM
overlay must preserve each untouched node's content, order and original typed
origin, including sibling fields and PAGE/layout.

0E2D70's mapping argument is significant. When nonnull/nonempty it can rewrite
the inserted kind3 payload's own tag, then traverses descendant tags. Callback
0E56F0 parses a tag, searches the16-byte mapping rows, and writes the found new
ID as value-kind4. Thus a field adapter cannot silently discard a nonidentity
map. A bounded first library route may support only identity registration,
but must derive/check every requested-to-actual pair from the exact successful
source application's active registry. It must refuse missing, conflicting or
renumbered entries. This is a library identity-map restriction, **not proof**
that the native115800 mapping vector is empty. Nonidentity source/DOM remapping
needs its own later producer and algorithm port.

After its edit loop,115800 searches the same original field for INPUT, reads
that INPUT's tag from the original DOM and resolves its C22 through the actual
original Ink.V128. When that selection is nonempty it invokes1156E0 on the
field. The helper recursively visits kind3 elements, resolves each existing
tag into the same original registry, and checks each nonempty tagged C22
against the retained INPUT selection with the real C21.V120 containment call.
Tag presence alone is not this check. A failed containment result causes the
receiver's post-validation/rollback branch even after source and DOM mutation.
The proposed library postcheck must therefore validate the full inserted tree's
tagged CHAR/WORD/TEXT ranges against the actual original INPUT domain. Missing
entries, out-of-domain ranges and unexpected tag encodings must not be accepted
as harmless unmatched strings.

115800 subsequently closes CB7 and commits or rolls back page history. That
native manager, original BE2 mutation journal, CBB source revisions, registered
row stream, page listeners and automatic cross-source rollback are still not
provided by the bounded library source owner. Successful original field DOM
work below must be named library publication, not native acceptance.

## Proposed next bounded runtime, pending review

The useful next scope is an explicit `LegacyLibraryOriginalFieldDom` owner plus
one `LegacyLibraryOriginalFieldDomPublication`, retaining the successful source
history before inference and consuming its genuine document/source application.
No runtime implementation is included in this checkpoint.

1. `history.PrepareFieldDom(actualOriginalInput)` runs before the history issues
   its one selected context. It retains the exact original bootstrap, historical
   PAGE graph, original name owner, chosen field/id and actual INPUT selection.
   The history retains this one DOM owner; if it is claimed, the later
   CreateSelectedInput must use that same original entry. Construction validates
   the entire PAGE/content/layout and all field/INPUT identities. The first
   implementation supports direct fresh fields with one INPUT, no prior
   textResult, no activeArea and no external edits. Other original fields stay
   present. This scope must refuse unsupported structure before NN.
2. Once genuine original-selected recognition has built and transferred its
   actual C4D and textResult payload, the DOM owner prepares a publication from
   that exact document. It verifies history-issued selected identity, source
   application, original compatibility, actual pending C4D and successful writer.
   No caller-supplied row, expected text, source name or readiness flag enters.
   The document retains the exact publication receipt.
3. Build a **new** field-relative edit, retaining the actual result payload and
   its source arena. On the supported original field[INPUT] its empty path and
   ordinal1 are derived from the actual original child scan. The old library
   export remains the old kind4/ordinal0 edit; it is never relabelled or consumed
   as the new field edit. Copy/re-intern payload names into the retained original
   name owner under explicitly documented library representation. Preallocate
   complete node/attribute/value/depth bounds before copying.
4. Run actual whole-kind3-field scratch clone, map every parent first, then
   simulate the new edit. Report Worked and Compatible separately. This result
   must be ready and successful **before original source application Run**.
   Preparing the original DOM only after source writes would reverse native
   preflight order. Claimed pending/incompatible/failed field preflight blocks
   original source execution; old unclaimed routes preserve old behavior.
5. Live field apply requires exact source ExecutionSucceeded and JournalComplete,
   not pending/failed/unsafe/rolled-back state, plus unchanged DOM epoch and live
   borrowed scope. The actual requested IDs must equal their actual active
   registry IDs. Clone/append textResult at derived ordinal1 and preserve INPUT,
   all attributes, siblings, other fields and layout. Record real completed
   copy/mutation prefixes. Perform full recursive original-INPUT tag/range
   post-validation, not a summary boolean supplied by the caller.
6. Increment a separately named library DOM epoch only on completed publication;
   it is not native field-state48 or cache version98/A8. A native-undefined clone
   null, entered cancellation, mutation failure or failed post-validation poisons
   this new library DOM lifetime and preserves diagnostic prefixes. Do not invent
   automatic original DOM rollback or let the old source-only Rollback leave a
   live inserted result referencing deleted IDs: once field apply enters, block
   that source-only inverse unless a future genuine combined DOM inverse exists.
   Preentry cancellation remains reusable. Closing DOM/history/scope prevents
   new live operations; immutable historical and active snapshots remain readable.

Lock order remains document receipt -> history -> new DOM gate -> private graph.
No callback from a held history/DOM lock may reenter the document. Existing
source history and kind4 DOM APIs keep their previous outputs when the new
field owner is unclaimed. The original bootstrap State remains historical;
only the named live DOM overlay is updated. Explicit library applications to
two different targets remain distinct receipts, never one edit applied twice.

The expected old seams are only the source-history file (retain chosen DOM
owner before issuing selection and consume its preflight/apply state) and
document file (claim/retain/validate the exact publication and expose the genuine
writer payload under its gate). A new kernel/arena can consume immutable original
bootstrap snapshots and original name interning without editing old bootstrap,
selected-context, NN, numerical/source kernels, global recognition or existing
kind4 target algorithms. Any additional seam requires a separate review.

## Verification required before runtime integration

Use genuine raw inference/document/source applications with both choices of
two original fields, plus one-field and multi-INPUT registries where each field
has its actual own INPUT. After inference, an independent oracle must reconstruct
the result payload from captured CHAR40/WORD48/ref24/TEXT32/line56, derive the
source command registry, clone the entire initial field for scratch simulation,
derive ordinal1 from actual children and independently execute final insertion.
It must compare complete PAGE graph, all attributes, every original sibling and
all result tag/ranges. Expected recognition labels are not inference inputs.

Prepared controls must be named separately: wrong selected context sharing the
same raw Document; wrong field and name owner; malformed field graph; ordinal0
attempt; stale epoch; missing/nonidentity registry mapping; out-of-INPUT range;
scratch clone/map allocation failure; live clone/append and cancellation prefix;
closed scope/history; duplicate apply; source-only rollback after DOM entry.
Actual fresh factory inputs cannot be claimed to have naturally produced the
prepared incompatible structures. Old source-history, original-selected document,
library kind4 DOM, compatibility and bootstrap Managed/Native captures must remain
unchanged. A new NativeAOT capture must match the independent managed capture.

full pinned PE fingerprints,10 complete function regions,8 virtual/service
bindings,147 instruction pins and5 exact literals. It reads bytes only and loads
no vendor DLL. This is a static original-field/ordinal/clone/map/postcheck contract,
not a tested runtime, quality improvement, complete engine or released feature.
