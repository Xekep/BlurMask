# Native18e960 horizontal prepared-ink stage

`LegacyCursiveHorizontalCuts.Apply` restores the complete prepared-ink horizontal stage `18018e960`, including its insertion paths. It consumes a `LegacyCursivePreparedInk` buffer and existing typed tags. **It is not the complete `191950` candidate producer:** the preceding loop-intersection and other tag-producing geometry must still run before this stage for full native behavior.

The stage groups eligible forward segments by two slope conditions, ends groups at steep segments, loop barriers or the physical stroke end, and preserves the native persistent strong-segment flag. Loop tags11,13,14 block groups; tag12 resets that barrier. The selected group is scanned for reversal tags7 and8. When there is exactly one reversal, additional existing-tag checks must pass on both sides.

Three reversal paths handle groups containing only7, only8 or both. They measure physical ink arc lengths, preserve sufficiently separated reversals, and insert tags4 or6 at explicit half-arc locations when the native predicates require it. The generic path measures signed distance from the endpoint chord and chooses positive/negative extrema; it may set an existing tag5 or insert a tag5 halfway between the selected extrema. Interpolated coordinates use float32 arithmetic. Each insertion goes through the recovered18dde0 prepared buffer operation, keeping provenance maps and updating only affected neighboring segments.

The generic path's missing arguments in decompiler output were checked against native instructions18fcdc–18fd5c: chord dx/dy are float subtractions, passed to `_hypotf`, normalized separately, and combined with point-relative normalized deltas. Instructions18fd60–18fd74 use `COMISS/JBE`. Unordered comparisons caused by a zero endpoint chord do not update extrema. A naive translation of the decompiler's `else` would incorrectly update the negative extremum for NaN; the independent implementation follows the disassembly. A dedicated control checks the resulting strict half-arc crossing and duplicate inserted endpoint.

Cleanup follows native masks0x1872 and0x19f2. The optional keep-one-anchor branch preserves only the last encountered tag4..6 while scanning backward and also preserves tags1,11,12. Both axis directions are explicit caller parameters; the Russian profile calls the primary direction. The six numeric settings are explicit and finite. `RussianVersion106` contains the exact serialized values from both Russian sampler nodes: slopes0.5/0.35, minimum arc0.2, long arc1.8, gap radius0.35 and reversal spacing0.25, with keep-one-anchor false. The console probe verifies them against the actual `.res` bytes.

`tools/LegacyCursiveHorizontal.Probe/reference_controls.py` generates768 independent scalar reference cases with original ink coordinates, typed loop/reversal tags, both axis directions and both cleanup modes. Of these,394 insert points. Controls compare every output coordinate, delta and segment length as float bits, every tag, physical stroke identity, original raw-index map and prepared stroke count. Additional controls cover a straight arc, zero endpoint chord, malformed settings, cancellation and original-buffer ownership. Managed and Windows NativeAOT runs are required before marking the stage ready.

The implementation remains a bounded research component. It has no proprietary SDK runtime dependency and does not launch the desktop application. It cannot yet be used to claim complete native cursive segmentation or Russian handwriting accuracy: the preceding `18018e1f0` loop-intersection stage, `180190350` baseline stage, final `180191430` marker-limit stage and the full `191950` branch controller remain separate work.
