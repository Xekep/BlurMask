# Owned English119 first rich WORD/TEXT components

`LegacyOwnedEnglish119PlainText.Materialize(terminal, allocation, token)` consumes
one completed `LegacyEnglish119TerminalResult` from the actual English-lite
source247/119 -> preprocessing -> sampler108/cuts -> cached NN -> primary ->
A8/B0/B8 -> terminal path. It produces the selected first rich glyph pool and
ordered WORD275 snapshots, including genuine interior delimiter words. It
does not expose a mutable pool, publisher, WORD builder or native pointers.

This is a first-controller result component. It is not full serialized TOP273,
the main dictionary controller, source720, UTF8 or accepted English text.
In particular no TOP18 acoustic-alphabet assignment has been established in
native1F42D0; the actual source alphabet here establishes symbol/category
provenance only. No acoustic alphabet is substituted into an unproved TOP slot.

## Ownership and policy

The private factory retains the same terminal/context, primary, source247,
119 model, 108 categories, pruned graph, raw source and prepared cut chronology.
It accepts the proven fresh ordinary135, no-trait, A4=1, one-surviving-terminal
scope. Fresh99/A8/E0 are derived upstream, not caller booleans. Capture0, C4false,
literal6Ctrue and resource B9false follow the exact selected-child construction
and invocation route. B9true word-geometry finalization/sorting remains refused.

The original descriptor retains `CurrentLineId=-1`. A separate assigned
descriptor records line0: secondary ctor16A17C starts guide-count80 at0,
16E972 appends/increments it, and16EAC1 stores `count-1` before the same-guide
geometry update. Ordered24C/265 preserve that assignment. This does not relabel
the ingress descriptor or borrow a RU frame.

Native6C bypasses alias/FFFD dispatch. Published labels remain literal, including
the actual F0003 label190. With99false, E2blank217 and E4closed211 skip glyph
allocation, scores and word-boundary publication, while the predecessor/source
walk continues. There is no replacement with a guessed character.

The assigned ordinary frontend1A0 uses actual category **values**, graph arcs,
cut bounds and guide height. The graph09=1/resource159=0 scope excludes the
unsupported assigned fallback; no both-unassigned branch is assumed away by
claiming container bit4 clear. Endpoints retain zero-span rows. Genuine interior
FFFB becomes the encoded count1 macro in the same pool, not a guessed space.

Glyph C uses the actual primary byte8/255. Glyph10 uses the same group's
candidate.vector10[owner88=0]; it does not use candidate24.field0. Glyph14 uses
the actual1C13A0 symbol/prototype request with ordinalFFFF/top20. The group is
already resolved from the selected node/arc; unused node/arc bytes in this
private portable request remain the old wrapper convention, not a claimed
native request16 wire dump. Header-owner1C is the first candidate vector score
and is stored separately from glyph40. No NN runs during materialization.

## Allocation boundary and bounds

`LegacyEnglish119PlainAllocationStorage` snapshots explicit120-byte WORD and
40-byte glyph allocator storage. There is no default pretending unknown bytes
are native zero. Empty WORD vector-pointer/count constraints32/88/104/96/112
are checked. Existing native constructor/reset writes overwrite their exact
fields; other bytes remain supplied residue. Detached immutable WORD/glyph
snapshots preserve every resulting byte.

The numeric loop is mechanically extracted from committed4a533ec; its inverse
substitutions yield SHA256
`a42ba5acc99f99ffbd767df23046322f1c8bbccc7758a0030940ba9760645e61`.
The three old RU wrappers keep their original public signatures, source setup,
strict single-word API and zero-allocation convention. Interior and literal
numeric policy kernels are shared without importing a RU source factory.

Portable resource bounds retain1..2047 selected cells, existing pool/WORD
budgets and one terminal. The new interior owner checks its cut point budget
before copying coordinates and caps cumulative uncached bbox visits at
1,048,576, with cancellation per visit. This is an explicit portable work cap,
not a native algorithm limit. No source result is returned until the operation
completes; cancellation leaves only a private, unreturned allocation prefix.
