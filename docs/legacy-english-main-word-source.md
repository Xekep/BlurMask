# English MAIN ordinary WORD source completion

The independent library now connects the existing genuine English MAIN graph
to its ordinary WORD producer, source-range projection, augmentation, ranking
and score normalization. It retains the same private source, glyph pool and
publication scope. This is an internal engine stage, not public English text
admission or evidence of cursive recognition quality.

The original four-network evaluation supplies confidence values without a
second neural pass. The selected actual MAIN resource has four middle-only
network families; unsupported optional presence and conversion modes refuse.
Active source/D0 epoch checks surround the detached diagnostic callback and
private cache publication. Default-null diagnostics allocate no observation.

The real21FFD0 flush sequence is preserved: a positive ordinary word is
published separately from the leading zero-span protocol flush. Source188
mode2 count/fill uses the retained seed graph, prepared-point map and original
metadata. Its private receipt cannot be replaced by equal caller arrays.
Augmentation scans actual compact bit8 candidates into the same glyph pool.
The original selected word remains protected on duplicate; ranking and
normalization follow the existing native-derived kernels.

The implementation explicitly refuses unsupported replacement labels,
auxiliary metadata, residual/nonordinary augmentation and selected checkbox
branches. Bounded forward traversal, source arrays and snapshots are
precharged before mutation. Existing9MiB payload/64MiB copies/16MiB visits
remain unchanged. These logical reservations are not a whole-process memory
or latency guarantee. Diagnostic source snapshots are optional, bounded to
128 points/arcs/groups and retain no source capabilities.

## Verification and its limits

One root-owned actual call used the unchanged three-point entry at index4 of
the pinned141-item test input. It completed in about1.22s under CPU2/affinity3
with a45s watchdog; this observation is not a general latency promise.
The earlier graph metrics were unchanged. Two real flushes produced two WORD
choices after one append and one protected duplicate, with quota2. Capture:
`04a55b4c2f1c435cbab421ad10c75f1476fbbfe6dc4d82858aac0b5c946d7846`.

An independent DATA audit replayed the26-byte source projection, both64-byte
flush packets, both120-byte working WORDs, the protected120-byte publication,
both final120-byte choices and all120 glyph-pool bytes. Confidence calibration
was recomputed from the three observed sets of four182-output vectors; network
inference and geometric separation derivation themselves were inputs to this
audit. Sixteen corrupted captures were rejected.

The observation chronology0/1/2 differs from the earlier compact-export
chronology0/2/1. The auditor validates unique(Group,Span) keys and complete
coverage; it does not equate those two orders or reorder the producer.
Source90's closed-label numerical branch remains unverified and refuses in
this audit. Actual count/fill invocation counts and intermediate72-byte walk
buffers are not exported; consumed walk channels are checked through the
resulting pool and counters. Private lifecycle checks are source-reviewed,
not established by detached DATA. TOP273, TEXT/UTF8 and public admission are
still to be connected.

The first diagnostic actual call failed because an early node0 observer read
geometry created only later. The observer was restored; optional separation
values are now copied from the later active final graph scope. That failed
capture is preserved as
`05f2466131f4605c82837ddce4309fc2a3f9a93d584fec8997cc856be40c0df5`.
The corrected source was run once; subsequent audit corrections reused the
same successful capture without another neural evaluation.

The source/prepared suites cover12 fixtures,216 count/fill pairs,264 reverse
merges,108 duplicate predicates,56 rank/mass cases and9 corruptions. CI runs
these controls and builds the explicit actual entry without invoking it.
Actual execution requires `--actual-entry MODELS PINNED141_INPUT FRESH_CAPTURE`;
`tools/LegacyEnglishWordSource.ActualEntry/audit_actual.py` takes that capture,
the pinned prior compact capture, original input, MAIN AK and a fresh report.
This stage follows RC13 and is not included in that release.
