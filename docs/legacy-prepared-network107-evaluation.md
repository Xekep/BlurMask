The public API still accepts explicitly prepared activation tables; it is not an automatic native activation factory.

The signed-int16 × signed-int8 dot uses32-bit wrapping accumulation and then wrapping multiplication by the unsigned row scale. Scalar backend `0EF430→0EF270` and SIMD backends `0EF5A0`/`0EF6B0` agree on this arithmetic (`PMADDWD`, `PADDD`,32-bit `IMUL`). Actual107 padding weights in all six retained networks are zero. This prepared API therefore supplies only the meaningful input columns. It refuses nonzero padding weights rather than inventing the contents of native allocation padding. A hidden dot equal toINT_MIN is also explicitly refused: native signed negation would leave the supported LUT domain. These are portable supported-domain boundaries.

`EvaluatePreparedRaw` exposes hidden dots/values and raw output dots. `EvaluatePreparedExp` deliberately selects the full unmasked EXP branch (`212.V50→0EAF90→0E82C0`).
