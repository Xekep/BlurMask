## Proposed minimal NEW-only source-query owner

Prefer a separately fresh owned query-session constructor; do NOT silently
change M's104 pool, expose M's mutable private factory, clone its opaque IDs,
or reuse an unrelated generic/prepared owner as a genuine controller.

Proposed NEW `LegacyEnglishFreshDictionaryQuerySession` consumes the exact same
M masks and V58 owner, later joined by reference to N.scorer.Masks. It performs
the fresh source-preparation branch: create its own empty bounded container,
derive exact acoustic/lexical maps from the same actual source/data, run the
unchanged generic map/context initializer into that container, and retain its
OWN source68 map, ordinary query ring and single-source selection/eligibility
receipt. This is a new source-binding phase for a fresh word-query invocation;
it does not reinterpret M's original masks-only container as a word pool or
claim pointer identity with it. M, its counts/copies and old outputs stay fixed.
All session query receipts and symbolic paths must refer to this one new source
binding, while its model/data/MAIN ink references remain the actual same owners.

Existing public generic kernels can be called privately without widening their
authority: `LegacyDictionaryInitialSymbolMaps.Prepare`, `CreateQuerySource`,
`LegacyPreparedDictionaryWorkingMap`, `LegacySymbolContextFactory` and its
same-container Capture/Restore. The NEW owner derives their inputs, supplies
private resolver/link callbacks and never exposes arbitrary callback/ID/flag
ingress. Native pool limits remain an explicit independent resource budget,
not the lexical alphabet count and not an alleged SDK default. Candidate
prototype: preflight initial86 plus the complete maximum number of future
query/graft insertions and their managed/page overhead BEFORE session claim;
choose the context bound from that exact work budget. Do not accept a smaller
bound and silently call null contexts valid ready results. Failure after entry
must retain its actual prefix and poison the session; old completed receipts
remain historical, never a fresh controller authority. Serialization or private
per-invocation state must preserve native page/ring encounter order.

Old runtime seam inventory for this proposed design: ZERO. M remains unchanged.
No arbitrary copied map becomes an owning selected-source receipt. If review
instead requires sharing M's existing container, that requires a separately
listed and approved M creation/capacity/lifetime seam; it is not implemented by
this proposal. Source-key/reference equality must be checked explicitly at each
N/M/V58/session join; equal sizes, costs, node IDs or hashes do not suffice.

N's frozen scorer contract has `Masks`, `Model.Source` and
`ScoreArc(node,ordinal)` returning immutable GroupId/Span/full220 class costs,

A genuine session `ReadStartup/Continue` entry must consume a separately sealed

the actual N/controller adapter under review, not set to0 as convenient missing

the session may only be labelled a bounded source-query preparation/transport
component; it is not a complete decoder. Node→terminal V58 receipts stay lexical
unless the new owner records every actual query edge and chosen real N arc.
Frontend128 geometry/qualifier/scoring, row allocation/recombination, native
scheduling, category/punctuation branches and final acceptance remain N's
separate static work. No original bounded beam is relabelled native.

This proposal therefore requests review of the source-session ownership branch
and exact request-admission contract FIRST. It does not request broad runtime
implementation of a complete controller before those caller dependencies are
closed. No masks, inference quality, bilingual arbitration or application change
is included. The model-specific raw checks do not take handwriting labels.
