# Raw input to configured main alternatives

`LegacyFreshMainConfiguredSingleLinePlainRecognition` is a separate owning
compositor. It keeps the actual fresh raw input owner and original source
document, runs first TEXT and source preprocessing, samples the resulting main
line, and constructs the CASE dictionary and main controller. Only then, before
that main controller is constructed, it applies the proved property18=2 path.
This is not a claim that a top-level engine property was forwarded into every
first-child factory. The existing default raw recognition method is unchanged.

The resulting main inference owns both2410 secondary entries. The configured
compact publisher and alternative assembly consume that exact pass and pooled
storage. No count1 terminal, parallel DIRECT dictionary, manually supplied frame,
expected word or renamed symbol is substituted. The new result holds the actual
InputOwner/SourceDocument, first preprocessing, sampled source/context, pass,
compact owner, geometry and alternative assembly. It is not cast or wrapped as
`LegacyFreshMainSingleLinePlainRecognitionResult`.

The current configured compact path supports one genuinely assigned main line
and fresh one-shot publication through node119. Longer input is explicitly
refused before main inference; it is not redirected into an unproved configured
LIVE publication route. First preprocessing and main decoding retain their
existing unsupported-branch refusals. Rescue, external associated sources,
enabled F4/repair, detailed equality and final application acceptance remain
outside this compositor. The result exposes raw WORD UTF8 pieces per active
alternative, without inventing joining spaces or choosing an acceptance score.

Resources and raw source document are owned snapshots. Complete compact,
alternative, WORD and stack allocation residue remains explicit. Pure extent
failure or entry cancellation leaves a prepared input reusable. Entering actual
preprocessing consumes the invocation, including a later exception. No failed
operation is hidden by constructing another raw run. Main logical-row storage
uses the same owned storage-provider pattern as the original default compositor.

## Actual evidence

The probe consumes one original four-node trajectory and nine pinned recorded
word-coordinate tracks from the existing corpus. The nine tracks lack pen-up
metadata and are explicitly supplied as one unsegmented path apiece. Their
expected transcriptions are never read. These are ten different inputs, not
twenty independent samples.

All ten complete the actual first/source/main/configured-result path, producing
twenty WORD alternatives and forty callbacks. The graphs have4,8,16,20,9,22,22,
7,15 and21 nodes; the configured compact pools contain1591..4077 records. There
are no ignored unsupported failures. Every observed pair has distinct native
glyph streams; this does not add a positive inferred-duplicate or rescue test.

An independent Python oracle scans every captured final2410 matrix and context
tree. It checks exclusion identities, selected costs, actual source counts,
WORD glyph labels against the raw AK alphabet, reset276 seed carry, rank/mass
publication and all4000 final273 allocation bytes. Source document/pass/pool
identity and30 lifecycle/preflight guards are checked by the headless probe.
Managed and fresh Windows NativeAOT captures are compared byte for byte.

This is producer/consumer and numerical evidence. It is not a CER evaluation,
proof that either alternative is the intended handwriting, a calibrated
confidence or an application AI-pen activation. The existing text-source wrapper
still needs a typed configured-candidate join to this actual input document;
the old count1 wrapper's ownership checks are preserved.
