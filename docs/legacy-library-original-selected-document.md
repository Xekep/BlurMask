# Original-selected document and registry continuation

`LegacyLibraryTextPublicationDocument.PrepareOriginalSelected(scope, words)`
continues the actual pre-NN original-selected publication scope through the
existing source/CHAR/WORD/TEXT postprocessors, selected INPUT geometry export,
counter handoff, range formatting, library DOM tree and edit transport. Its
scope, source registry, INPUT/C22,2DA/Seed, shared3E and pending C4D keep their
original identities. It never replaces a Seed after inference.

The native source/command proof is
`legacy-original-selected-document-continuation.md`. This runtime consumes
that proof; it does not invent an original page receiver or native acceptance.
The original bootstrap's library history journal remains distinct from
CBB/store/revisions/CB7. The explicit library kind4 DOM target also remains
distinct from the original selected PAGE reader.

## Exact source export and counter transport

The internal common `LegacyLibrarySelectedInputBinding` resolves the chosen
source-tag entry from its actual selected registry. `ExportIdentity` retains
that exact entry, verifies its original entry identity, and calls the selected
owner's already checked current-view exporter. The transform result exposes
`OriginalSelectedSourceInput` and `SourceGeometry`. The previous `SourceExport`
getter throws on this new source rather than constructing an old context.

`LegacyFreshMainDocumentInputTransforms.ApplyOriginalSelected(cleanup)` keeps
the native order: claim the invocation, export the selected C22, replace the
same seed's108 owner unconditionally, then test export status before026EF0.
The supported actual INPUT has no span children, so its retained DAF32 vector
is empty. Identity exclusion produces no transform80 rows. A prepared failed
export test retains a nonempty new seed vector, preserves the released initial
vector identity, refuses retry and prevents the counter handoff. Those bytes
are a labelled fault control, not produced nonidentity recognition geometry.

The pending counter's old value is the common binding's actual Next. For two
retained full-domain INPUT entries this is2 regardless of whether the chosen
field's tag is0 or1. CHAR/WORD/TEXT pending commands therefore start at2.
The C4D trailing operation7 retains old2 and the actual final tuple counter.
The same transaction is transferred with the BE2 edit; comparisons use the
exact binding reference, not matching tag numbers or raw document identity
alone. Transfer reserve failure retains both incoming slots for its existing
checked retry. No new caller success flag or command list is accepted.

## Active selected registry and original-domain preflight

`LegacyLibrarySelectedInputRegistryReplay.PrepareOriginalSelected(document)`
retains the successfully transferred C4D and the same selected owner. Its
initial ID set, Max, Next and budget include every retained selected registry
entry. This is essential when chosen tag0 coexists with INPUT1. Operation4
preserves exact requested ID/category100/name/ranges, and operation7 only
advances the counter when the native comparison requires it. The existing
numeric AddExplicit/ApplyCounter implementations are unchanged.

`InitialRegistryIds` is an immutable copied view. `OriginalSelectedInitialContext`
and `OriginalSelectedInput` retain the actual selected context/entry;
individual replay selections expose `OriginalSelectedTargetContext`. Older
`InitialContext`, `Input` and `TargetContext` getters throw on this route.
`Selections` still contains only new operation4 clones. The original and the
selected historical registry snapshots are never rewritten by the overlay.

The named
`LegacyLibraryOriginalInputPatchCompatibility.PrepareOriginalSelected(replay)`
consumes that exact receipt and retains `OriginalBootstrap` plus
`OriginalBootstrapInput`. It rebuilds the raw C21 domain from the original
CurrentView and checks it against both the original INPUT and chosen selected
child C22. It retains the previous separate Worked/Compatible semantics and
source-presence checks. This is library compatibility over an actual retained
original domain, not a claim to have reconstructed original C4D.F8 or CBB.
The previous concrete OriginalContext/OriginalInput getters remain strict.

Once optional original compatibility or DOM scratch compatibility is claimed,
its successful compatible result gates registry execution. A claimed pending
or failed registry replay gates explicit DOM apply. Both outcomes are retained
by the same document receipt. Successful replay alone does not apply DOM;
`ApplyToLibraryTarget` remains the explicit library-target operation.

The lock order and lifetime are unchanged: document, then compatibility or
replay, with checked target scope where needed. Preentry cancellation is
reusable; entered failures retain prefixes and poison their existing owners.
Context disposal closes new context entry while the publication lease keeps
required strings/result data alive. Scope disposal invalidates live document,
export and replay operations; historical scalar/range/tree snapshots survive.
No broader same-context concurrency guarantee is introduced.

## Compatibility and verification

The old `Document.Prepare` and `InputTransforms.Apply` routes preserve their
early unsupported result for this original-selected source. The new named
entrypoints carry the new source. All previous public signatures, numerical
algorithms and concrete old-route getter behavior remain unchanged. Existing
pre-NN publication captures therefore remain identical, including their old
early-boundary controls. No first-candidate, model, NN, global-owner or DOM
tree kernel changes belong to this batch.

The new `LegacyOriginalSelectedDocument.Probe` uses three actual raw samples,
including reversed physical order, and chooses both fields for six positive
NN/publication/document paths. Its capture retains raw CHAR40/WORD48/ref24,
TEXT32/line56, selected C22, source tag, full initial registry, matrices and
actual commands. The independent Python oracle reconstructs full trees,
node/name order, command bytes, range links, transfer rows and registry prefix
counters from those post-inference records. Expected labels never enter
recognition.

Managed and NativeAOT verify6 positive trees/472 nodes,5 DOM/transport prefixes,
6 registry/preflight prefixes,1 failed-transform swap and222 owner/lifetime
guards. The probe performs18 actual scoped inference invocations in total;
all failure scopes also use genuine fresh inference owners.
Prepared incompatibility and allocation failures are labelled explicitly.
The actual compatible controls use the real original/selected owners.

UUID initialization deliberately uses library cryptographic entropy. Each
tree is checked against its actual captured identifier before normalizing only
UUID fields for Managed/Native and old-golden parity. The new canonical stable
capture SHA is
`e03ede2b8fa367a782c769811a7babd676dfe197c091588c632a2ebe95c1ef12`.
