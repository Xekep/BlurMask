## Original source application and rollback are distinct algorithms

Original C20.V188 dispatches C4D.service38=Ink07E210 because original58 is
nonnull. The method begins the history lifetime on that original C4D. A failed
begin returns false before application. After a successful begin it requires
the C4D's exact F8 source target, sets recording108=1, and calls078090 with
the incoming transaction+8 and cloneSelections=true. It keeps recording108=1
after that call even when execution failed, ends the begun history scope, and
returns the saved execution status. The selected clone's history-disabled
direct078090 branch omits these required original objects.

Original observer0797F0/079A10 creates the history command record around the
actual registration operation. Its record is a forward operation4 with the
original-target C22 clone, name/category and returned ID. It is not valid to
rename the incoming result C4D as this generated history frame. Allocation,
recording mode, observer ordering and completed registration determine which
history commands actually exist.

The reverse walker is C4D.primary.V18=077570, whereas the forward generic
executor is078090.077570 requires F8, disables recording108, starts from the
frame's tail pointer10 and walks command.previous10. Its real opcode4 branch
calls original C20.VE8=069630 to delete the exact registered ID. Its opcode7
branch reads C51.Max through service18, not C51.Next. It only invokes the
Next setter28 with oldCounter20 when Max is below that old counter. The code
sets recording108=1 on successful completion; early refusal preserves the
entered failure prefix instead of unconditionally restoring that flag.

This has an observable consequence: undoing newly added selections does not
justify restoring the complete original counter bytes. A generated history
frame may contain only operation4 records, because the incoming trailing
operation7 is skipped once explicit-ID registration has already advanced
Next. Removing those IDs can leave Next monotonically advanced. A synthetic
"restore initial Next" shortcut would differ from the native transaction.

Deletion itself is an unported operation in this owning path.069630 looks up
the actual ID, retains its C22/name/category, runs before/after observer

releases retained data. The C51 structural removal and those original C4D/CB7
observer outcomes need their exact bounded contracts before an owning rollback
can be advertised. Existing selected-registry addition controls do not prove
this branch. In particular C51.service40 is09F2A0, not the removal48 callback.
