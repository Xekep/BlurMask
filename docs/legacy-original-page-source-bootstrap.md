This static checkpoint follows the actual original CBB/C81 source route after
the [registered history proof](legacy-registered-text-patch-history.md). It
changes no runtime and does not identify a library target with an SDK page.
The smallest remaining producer is before the receiver's preflights: creation
and binding of the original history-enabled page/field owners themselves.

## Smallest defensible next owning operation

No new public acceptance API is justified by the existing owners. Current
publication receipts possess the selected input, same-source pending C4D and a
new no-history target. They do not possess the original C81/store/history node,
original CB7, actual original DOM field/id or registered field/cache revisions.
Another gate over the same snapshots would not create these producers.

The next coherent ownership block is a fresh original page/field bootstrap,
before C51 INPUT registration and selected cloning. It must jointly produce
the original C20 and history-enabled PAGE DOM, the same CB7/history node and its
source observers, then the actual DOM field with id/tag and its C22 registry
entries. That owner can later supply00D0C0's source40/revision48 and the actual
input-diff version stream. Existing Seed/INPUT objects cannot be rebound to it
after publication, nor can their known library INPUT0 allocation order be
assumed to be this page's allocation order.

Before implementing that bootstrap, the remaining focused dependencies are:

* Base70/history-manager ownership used by original BE2 and C4D observers,
  including real begin/end and inverse-operation recording. Constructor flag1
  is not a substitute for those callbacks or an excuse to discard them.
* Original field/INPUT DOM insertion and CB7 C43/BDA callbacks, including
  registry/tag allocation order and field `@id` production. CB5's empty page
  skeleton alone does not provide a recognized textField or retained INPUT.
* Native store/history-node parent identity and field generation/revision
  transport. A separately named library-owned store/entropy adaptation may be
  possible once those contracts are restored, but it cannot silently stand in
  for a live SDK package/page.

The pure CB5 skeleton is small enough to port, but implementing it with a
no-history arena and then calling it the actual original page would omit the
critical flag1 observer producer. Conversely, an explicit library history
recorder plus the scoped original field insertion path would be new executable
data production, rather than another prepared success flag. That is the next
proposed runtime scope after its observer/field contracts are pinned.

`audit_original_page_source_bootstrap.py OUTPUT` verifies the full Document and
Engine PE hashes, fresh caller/constructor/observer bindings, completed field
metadata writes and input-diff version order. The original registered
receiver/history audit remains its dependency. No vendor code is executed.
