## Lifecycle and budgets

Aggregate preflight validates every completed row origin/child Preparation,
descriptor partition, source interval and actual membership before reservation
and copying large buffers. Existing limits are physical256/current4096 points,
descriptors511, source rows4096, projected ranges65536,24B range visits1048576,
and portable256 source items per descriptor. The latter is an existing helper
limit, not advertised as a native constant. Conservative full-grid range work is
checked against24D's16777216-visit bound before copies.265 retains its aggregate
4096-output-point bound; an entered expansion failure poisons continuation.

A canceled validation leaves the parent unreserved. A prepared owner whose Run
is canceled before entry can still run; after entry, failure/cancellation poisons
retry and retains the latest completed-stage snapshot in production. The parent cannot reserve a
second continuation even after failure. No old publication rows, child result
storage or native pointers are rolled back. Snapshots, descriptors, guides,
points, rows, keys and traces are defensive/immutable. Existing parent publication
state remains a completed immutable input to this separate once-only stage.

The parent gate is held only while constructing/reserving the new preparation.
No child operations or external callbacks occur under it. Run and snapshots use
a distinct continuation gate and do not reacquire the parent gate.

## V2 snapshot retention and copy envelope

Public `Prepare` selects production retention before parent reservation. Public
`Run` keeps zero or one completed snapshot: `CopySnapshots()` returns only the
latest completed image. The scalar trace and line-fit results retain all stages.
A replacement image is fully constructed before replacing the old image under
the continuation gate. Constructor failure preserves the old completed image;
entered failure still poisons retry. Completion returns `post265` as the image.
Previously returned immutable snapshots remain readable, so caller-retained
public copies are outside this owner's retention envelope.

Only internal `PrepareDiagnostic` selects complete snapshot history. That policy
cannot be changed by Run, and both modes perform copy-budget checks before large
row/point copies and before reserving the parent. There is no caller assertion
that an unchecked input has passed a diagnostic budget.

The conservative copy accounting uses padded64-byte array/object allowances,
8-byte slots,8-byte points,4-byte keys, and charges descriptor/guide arrays,
stroke and point arrays, rows' reference slots, key staging, and snapshot headers.
Shared immutable source-row payloads are not copied by a snapshot. For D complete
descriptors, O ordinary descriptors, S physical strokes and R rows the maximum
image charge is `512+160D+120O+144S+65536+8R` bytes. All stages use the4096-point
output cap in that upper bound, including stages with smaller prefixes. Maximum
snapshot count is `2O+4`. Production checks a two-image peak against512KiB and
whole snapshot copy work against128MiB; diagnostic checks whole retained/work
charge against32MiB. These are bounded copy envelopes, not process RSS or
allocator/GC guarantees. Other algorithm working buffers, model resources and
callers' copies are not included.

Arithmetic-only adversarial controls admit production D511/O256/S256/R4096:
image248160, two-image496320,516 images of cumulative work128050560 bytes.
Full diagnostic retention rejects that shape; with the same D/S/R, O72 is within
32MiB and O73 is refused. No giant arrays are allocated for these controls.
The141 genuine captures use internal diagnostic history for the independent
numeric oracle. A second actual parent runs the public production path for each
input. Final image bytes, global ranges, point keys, complete metadata identities,
fit/scalar results, trace and lifecycle agree exactly. Seven independent stage
failure controls likewise compare production latest-prefix images and all scalar
state with diagnostic full history. Both Managed and NativeAOT run these checks.
The previous V1 full diagnostic capture values remain exact except guard count.
