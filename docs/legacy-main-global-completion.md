# Owned global results to completed glyph bytes

`LegacyFreshMainGlobalPublishedCompletion.Prepare` accepts the actual positive
result returned by `LegacyFreshMainRecognitionContext.PrepareGlobal(...).Run`.
It retains that selected postpublication owner, session and complete callback
sequence. A no-winner result cannot manufacture an empty completed result.

`Run` composes the existing checked stages in order:

1. Capture the first alternative and score channels from the actual final
   publication, with explicit400-byte allocation contents.
2. Apply quote cleanup to that same session's WORD list with two distinct
   caller-owned four-byte scratch slots.
3. Represent the proven fresh-configuration F4 zero-write return. The enabled
   glyph-rewrite body is still unported.
4. Prepare and execute dynamic-control import from this exact published
   snapshot into a separate copied pool and WORD lifecycle.
5. Complete the default UTF8 helper independently for each glyph, then join
   the resulting bytes within each actual WORD.

No supplied labels, replacement text, old terminal/snapshot substitution or
document-acceptance flag enters this API. WORDs retain their native head order;
the wrapper does not invent spaces or line breaks between them.

Invalid storage shapes, overlapping scratch slots and an already-cancelled
token fail before the invocation is consumed. Once capture starts, exceptions
and cancellation retain the completed stage prefix and prevent restart.
The quote cleanup's shared session claim also blocks replay by constructing
another wrapper around the same raw result. `Words` is populated only after
all glyphs finish; unsupported codecs, controls and import branches retain
their existing explicit refusals.

This is a library composition, not an application default or an accepted
transcription. It does not establish Russian cursive quality, restore the
remaining source/document transforms, or connect the native Math2 beam driver.

The dedicated `LegacyMainGlobalCompletion.Probe` checks eight distinct source
fixtures with four allocator-residue variants each, not32 independent accuracy
samples. It verifies161 preflight, cancellation, replay and no-winner guards;
32 completed WORDs and92 glyphs; unchanged cached model evaluations; and a
separate124-node no-winner that cannot enter completion. An independent raw-AK
and dynamic-control oracle compares complete imported pools and output bytes.
Managed and fresh Windows Native AOT captures agree byte-for-byte, SHA256
`5ebd883d862384d4061828a94f6ab4157f76d499d37bee2aee24191e0b524f0d`.
Actual fixture winners are ordinary letters and punctuation; prepared positive
circled/codec cases remain covered by the separate per-glyph completion probe.
The headless app build and console AI checks also pass without enabling this
path as the default recognizer.

The probe also accepts an optional recorded-manifest and word index after its
11 normal resource/output arguments. This mode reads pinned coordinates and
track hashes only, treating the missing pen-up events explicitly as one path.
`tools/handwriting/evaluate_global_completed_words.py` evaluates expected labels
only after all nine captures and independent raw-resource audits complete.

These are the same nine single-path tracks, not new writers or a held-out
