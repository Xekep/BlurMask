# Owned fresh main input preparation

`LegacyFreshMainOwnedInputPreparation` accepts raw physical strokes, the pinned
main and embedded line resources, runtime activations and publication data. It
composes the existing actual2E3 memberships, descriptor split, physical reorder,
first-child NN/cache/pruned-graph recognition, source720 publication and
24B/24D/29B/265 preparation. Masks, first results, labels, boxes and guides are
produced inside those owners.

The additive internal `PrepareForOwnedFactory` entry shares the first recognizer's
implementation with its unchanged public entry. It validates the selected source
snapshot against the submission's SHA and profile before model parsing, and keeps
the exact first factory/frame identity. This closes the ownership gap between
`LegacyFreshMainFirstResultLines` submissions and the existing owning first NN
recognizer. It does not construct a replacement factory with equal model bytes.
Primitive endpoint scope obtains each raw count from the actual108 ending-key
owner, preserving trailing duplicates rather than inferring the count from the
last retained starting key. The old public four-fixture/57NN oracle is unchanged.

`RunFirstStage` produces one owned result per real ordinary descriptor.
`CompletePostprocessing` checks the exact result/submission identities before
publishing source720 intervals and main guides. It refuses a foreign first stage.
An actual first result that publishes no word is refused: the main24A fallback
lifecycle has not been restored by this owner. It never inserts a placeholder
glyph or a box-derived replacement guide.

The native bindings retained here are `1680D0`'s grouping/reorder chain,
`158970`'s descriptor loop and `157C60` first submissions, `156950` source720
publication, `170400`/`16F6F0` main24B transfer and `173C10` per-guide265 inputs.
The static auditor pins the PE and verifies these bindings without executing it.
The already restored child map, source exponent, category and guide owners remain
responsible for their numerical algorithms.

## Actual diagnostics and remaining boundaries

The new probe runs seven original coordinate inputs with no expected text supplied
to recognition. Four complete this preprocessing stage. A reversed two-row input
produces two ordinary descriptors, a kind3 separator, two actual first submissions,
four source720 rows and two main guides. Two pairs of horizontally separated printed
shapes also complete the supported single-word first-result path.

Three other inputs, including wider two-word gaps and an original English-letter
trajectory, reach the existing first materializer's actual `WordBoundaryBit`
refusal. They are recorded as unsupported, rather than having the boundary cleared
or a result substituted. The supported two-word-shaped inputs do not demonstrate
correct word segmentation: their actual first trace contains one word.

The independent auditor reconstructs the192-label acoustic mask directly from the
resource, checks315 finite primary/B8 cells and14 real source720 rows, then solves
five main guide fits with the independent NumPy IRLS reference and checks each
physical deskew transform. Seven owner/resource/cancellation/remaining-sampler
guards and trailing-duplicate ending-key controls are exercised. An all-identical
four-point input retains one point with ending key3, rather than the incorrect
retained-count endpoint0. Its current temporal classifier rejects zero spatial
extent; the probe records that additional limitation without scoring a substitute
point glyph. These are
component and ownership checks; no Russian or English accuracy threshold is
claimed.

The resulting multi-descriptor source is genuine, but the existing
`LegacyFreshMainSingleLineSampler` still refuses more than one descriptor. A
multi-descriptor main graph must preserve global source keys, descriptor kinds,
line IDs and context ownership. Selecting one line or supplying manual geometry
would not close that gap. Full first273 multiword publication, empty-first24A and
the final main-language winner remain separate dependencies.

The probe takes eight arguments: AK, engine profile, separation profile, case data,
publication data, embedded line30, embedded line50 and capture path. Run its
`audit_output.py` with AK and that capture; run
`tools/handwriting/audit_main_owned_input.py --output <report>` for the optional
static PE audit. The old `LegacyFirstOwnedRecognition.Probe` and its independent
audit must also pass after changes to the shared first core.
