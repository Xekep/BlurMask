# English node0 and retained number source: development checkpoint

This checkpoint records isolated source work, not a restored recognizer. These
source drafts remain outside the production tree. Neither the application
recognizer nor its defaults or release version changed.

The English node0 increment7 draft joins the actual initial primary ordinal
span, accepted FIRST candidates, two sorting/merging stages, live heap rebuild,
quota31, secondary materialization and the common cleanup/source reset. It
preserves the initialized prefix and the separately defined inactive backing
regions. Every complete entry still refuses after the original pass because
final receipt/export and whole-operation accounting are unfinished.

An independent Python transcription of the iterative source matched all six
intermediate byte images, counts, capacities and156 secondary ordinals in28
prepared reference cases. Those original cases are not full-method admission
tests:1,357 active records have an arbitrary BYTE32 that the full FIRST entry
rejects. A separate derived comparison changes only that byte to FF and
recomputes its expected images with the independent native reference; all28
comparisons pass. Original goldens remain unchanged. No C# entry was executed.

The exact frozen English draft compiled in an isolated tree:764 C# files,
zero warnings and errors. Read-only PE metadata inspection of that output
shows the Node0Sort/Push/Compare local-function frame is a value type, with no
array allocation, boxing or delegate construction in those selected methods.
Their three object constructions are exceptions immediately followed by throw.
This finding does not cover other descriptor closures, transitive helpers,
CLR overhead, memory use or the whole algorithm.

The separate number TRUE-language draft retains actual source cursor objects
before closing its old Engine. Independent source review checked all three

provide this retained state.

## Blocking work before runtime integration

The English draft's existing terminal-index reservation is demonstrably too
small for its current getter-heavy implementation. Under the documented logical
source-operation convention, packed-label and child-range reads require at
least23 named calls per node. Adding just one token check and two stack reads
per node gives17,330,222 operations over666,547 nodes, already exceeding the
16 Mi whole-continuation visit ceiling by553,006, before the other work. A
private cached packed-reader redesign is in progress; no increased constant or
changed accounting unit has been accepted as a fix.

The phase1 source also needs expanded per-site accounting. Its current swap and
authentication charges exceed the earlier planned allowances; the old planned
3 Mi visit slice cannot be reused as a proof. This conservative-bound mismatch
alone does not establish that a real admitted input exhausts that slice.
Receipt/export, preparation-time BCL work and the whole ownership oracle remain
open. Passing compilation and prepared comparisons does not open execution.

Russian cursive, automatic text/formula selection, accepted text transport and
end-to-end recognition quality remain unfinished. This checkpoint provides no
new handwriting accuracy result and is not an RC release.
