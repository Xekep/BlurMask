source drafts remain outside the production tree. Neither the application
recognizer nor its defaults or release version changed.

span, accepted FIRST candidates, two sorting/merging stages, live heap rebuild,

## Blocking work before runtime integration

The English draft's existing terminal-index reservation is demonstrably too
small for its current getter-heavy implementation. Under the documented logical
source-operation convention, packed-label and child-range reads require at
least23 named calls per node. Adding just one token check and two stack reads
per node gives17,330,222 operations over666,547 nodes, already exceeding the
16 Mi whole-continuation visit ceiling by553,006, before the other work. A
private cached packed-reader redesign is in progress; no increased constant or
changed accounting unit has been accepted as a fix.

The phase1 source also needs expanded per-site accounting. Its current swap and
authentication charges exceed the earlier planned allowances; the old planned
3 Mi visit slice cannot be reused as a proof. This conservative-bound mismatch
alone does not establish that a real admitted input exhausts that slice.
Receipt/export, preparation-time BCL work and the whole ownership oracle remain
open. Passing compilation and prepared comparisons does not open execution.

Russian cursive, automatic text/formula selection, accepted text transport and
end-to-end recognition quality remain unfinished. This checkpoint provides no
new handwriting accuracy result and is not an RC release.
