# Math candidate DOM schema and third Ink clone

This read-only proof connects the complete028070/027E20 bodies to actual
selected C20 cloning, C51 counters, C21 serialization and DAF transform defaults.
It implements no runtime publisher, native edit receiver or formula acceptance.
No vendor library is loaded or executed.

## Three distinct Ink owners

028070 receives the recognition packet's selected C20 at packet+08. At02817A
it reads that owner's table;028190 passes that SAME owner in RDX,028185 sets
R8b=1,02819A selects V170,0281A5/1AA set the two trailing flags to1 and0281B9
calls it. The returned pointer is stored separately at0281BC and retained in

06E120 constructs a NEW C20 through its parameterized constructor, then calls
06D2C0 on that destination and the selected source. The all-raw flag1 clears
the optional selection, so this caller clones the complete raw/current domain
and registry rather than only a convenient chosen range. Its final flag1
sets the clone's history-constructor switch to0. The third owner is not the
original page Ink and is not the selected NN/C23 owner itself.

06D2C0 iterates the source C51, clones each retained C22 against the NEW C20,
registers each explicit original ID/name/category, checks the returned ID,
then reads SOURCE C51.Next through V20 and writes TARGET Next through V28.
The registered C51 table0E78A0 binds V28 to09ED40, which only accepts a counter
strictly greater than the target's maximum live ID. The complete prior clone
proof remains a dependency; no equal-shaped text INPUT owner is substituted.

Thus the current one-field positive source becomes INPUT0/category102/Next1
in a third independent Ink registry, with C22s owned by that third registry.
Original and selected INPUT0/Next1 remain unchanged during candidate building.
New Math selections are registered against that exact third owner and advance
ITS counter. This preserves native subsequent ID accounting. Registration
against the selected NN owner, or cloning only after allocating output IDs,
would describe a different algorithm.

CB8's032C00 retains it at object+10 and retains the supplied temporary BCC
at+18. The preexisting CB8 proof pins V28, V40 and V50 against object+10.
After temporary publication,028946..02896D asks the unchanged selected C20
for its V178 Ink edit relative to the modified THIRD owner; only a later

application of that edit to the original page.

## Separate DOMs and names

028070 constructs a temporary BCC with constructor byte0=0 and the actual
selected DOM's name owner. It deep-clones the selected mathField into that
temporary BCC and finds/creates its mathResult. CB8 then creates ANOTHER BCC
sharing the retained name owner and creates its own named mathResult root.
The root name in the descriptor is a name string, never a cloned subtree.

New sequence/symbol and fallback metadata are built in the CB8-owned BCC.
The initial old-tag scan uses the temporary field's old mathResult. V10 builds
an edit between these distinct roots, temporaryBCC.V228 applies that edit,
and ONLY THEN V40 resolves tags on the temporary field's replacement result.
V48(false)/V50 follow. V230 releases the remaining edit storage on both success and
late failure paths. A detached list of caller tags does not provide this
DOM/edit ownership. The exact payload cloning, application and cleanup are
pinned in [the temporary patch proof](legacy-math2-temporary-patch-application.md).
Mutating a candidate tree directly must be described as
a library adaptation unless that patch path is actually implemented.

## Exact symbol and fallback schema

For each actual40-byte outer row,027E20 creates `symbol` in the CB8-owned BCC.
For nonempty ranges it formats the SAME C21 ranges through registered service
V180=083DF0, writes string `range`, calls CB8.V28 with `MATH_SYMBOL`, and writes
the NEGATED temporary ID to typed INT64 `tag` through V128.

The registration call occurs even after range serialization or range-attribute
failure; the earlier success condition is tested AFTER registration. Its
counter/linked-entry prefix therefore cannot be rolled back implicitly.
Freeze compares actual complete C21 range vectors through V E8=081700. The
FIRST equal freeze row is decisive: its byte1C determines whether BOOL `freeze`
is written. A later matching true flag cannot override an earlier false match.
An empty range bypasses range/tag/freeze work.

Text uses the first alternative's first pointer only. It does not concatenate
alternatives, use the byte-count/scalar as a confidence, add spaces or parse
table-marker text into a typeset formula. Empty alternatives pass null to the
text-node constructor. Text-node construction failure destroys the new symbol.
The native append call's return is ignored at028025; the corresponding caller
append at02839A is also unchecked. A portable implementation that rejects these
failures must state that stronger semantic contract, not claim exact native
failure equivalence.

For nonempty symbol output the CB8 root receives, in order:

1. `sequence`, containing the actual ordered symbol nodes.
2. `transforms`, ONLY if the actual DAF filtered transform list is nonempty.
3. `symbolSegmentList` / `symbolSegment`, whose `range` is the serialized full
   actual INPUT selection, not a union reconstructed from retained symbols.
4. `symbolCandidate` inside that segment, with `nrs` typed FLOAT32 positive0,
   then `char` containing the literal text `?` at20CA94.
5. `mathTerminalNode` directly under mathResult, with string `name=""`, string
   `ref` equal to the same full INPUT range, INT32 `selected=0`, and INT64
   `tag=-CB8.V28("MATH_NODE", actualInputRanges)`.

The `nrs` caller also places FFFFFFFF in its following stack argument. It is
not nrs=-1: V138=0EDBC0 creates a type10 value from the zero FLOAT32 argument.
Likewise `selected` uses V118=0EDB00/type7, while freeze uses V148=0EDCA0/type6
and tag uses V128=0EDA40/type4. These typed setters are pinned separately.
The MATH_NODE registration call is reached even after preceding metadata
failure, before that success flag is tested. No whole-candidate rollback is
implied by the final failure return.

This is a fallback candidate schema; it is not final mathematical layout,
an evaluated expression, recognized semantic `char` content or accepted result.
Native no-symbol/prior-result behavior is distinct and remains outside the
current positive source producer.

## Ranges and fresh defaults

C21 V180 is the already checked083DF0 formatter. It preserves raw source IDs,
fractional coordinates, delimiter modes and uppercase `U` separators. It uses
the native canonical-copy branch, not arbitrary sorting/interval formatting.
Text-specific first-byte brace rewriting is NOT present in027E20 or028070.
The existing tracked document-bound formatter can be reused without inventing
a Math-only coordinate convention; source ranges and C51 IDs remain distinct.

0283D4 passes the selected NN/C23 C20, not the third registry, to DAF.V30.
The call sets filterIdentity=1. Registered DAF table1ED790+30 is030E20, which
calls that SAME C20.V1A8=06F080 and converts actual64-byte transform rows into
its80-byte output rows. 06F080 obtains each raw/current matrix through06B7F0
and omits an EXACT identity six-double matrix when the filter is enabled.
No approximate epsilon test or NaN-as-identity shortcut is justified.

The raw-current-view dependency proves ordinary C49/full coverage, no C25,
and identity construction/matching for this bounded input. Therefore the
current positive factory's filtered DAF list is empty and no transforms node
is added. Nonidentity/imported/C25 cases require their real owners and rows;
they must not be silently discarded as if this fresh default covered them.

The freeze vector starts null/count0 in02AF50. A prior mathResult sequence
would enter02A440 and produce32-byte freeze rows. The fresh current source
has no such result, so that producer is skipped.029290 passes this vector to

proof hashes all three complete bodies and does not invent nonempty prepared
freeze state as genuine fresh inference.027E20 still pins the full matching
branch for future replay/import work.
