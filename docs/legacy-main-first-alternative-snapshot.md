# First main alternative: post-callback ownership snapshot

`LegacyOwnedMainFirstAlternativeSnapshot` joins a real selected CASE terminal,
its completed ordinary glyph/publication session and the numerical main result
channels. It captures a successful post-callback state. It does not execute the
native allocation-before-callback failure order, construct a complete TOP273
header, search further alternatives or perform quote/21F320 normalization.

The convenience overload accepts `LegacyFreshMainSingleLinePlainRecognitionResult`.
The lower overload accepts its actual terminal, session and complete typed
publication tokens, allowing the existing recorded-coordinate ingress to use
the identical owner checks without manufacturing a raw-result object.

## Proven owners and storage

- Source count is actual completed pass node count, equal to the identical
  policy/controller graph. Native loads controller2310 at227271 and saves it
  as the divisor count at22727C. Selected beam field22 is not this count.
- `WordHead18` retains the actual publisher head. All successful callback tokens
  must name this exact session in native ordinal order. Walking their nonnull
  published nodes backwards must consume precisely the current prepended list.
  External extra publication, foreign/missing/repeated tokens and incomplete
  sessions are refused. The same real glyph pool remains the WORD owner.
- `BeamOwner20` is actual compact materialization, with terminal winner ordinal
  and a copied full88-byte **post207CB0** row. The terminal's diagnostic earlier
  copy has prepublication6/22 metadata and is not substituted for this row.
- Native13BD40 appends one alternative by growing capacity from0 to10 and using
  a single400-byte allocation. It constructs the first40 bytes in-place using
  class279/141540. There is no second40-byte allocation in this API. Inactive
  capacity retains the caller's explicit360 residue bytes.
- The row's VT0, WORD-list pointer18 and beam pointer20 are portable zero
  placeholders. Their real class/source/list identities are represented by the
  typed owner properties; no managed identifier is written as a fake address.

The internal40-byte constructor kernel exists only to verify exact in-place
initialization: zero08qword/10dword/18qword/20qword and floatMax14, with a zero
portable class279 VT. The native descriptor installs that VT before141540.

## Fresh first-result policy

The accepted policy is the checked fresh NEW20E main kind0x135 source, mode0,
secondary1, EC0, tracefalse, no associated source and inactive rescue. It has
no public property/setter inputs changing configuration99/A8: fresh00C860
zeroes qword98 and qwordA4, covering those bytes. On the first valid output,
227634..227655 therefore stores the selected total as integer reference and
sign-extended TOP78. The snapshot derives this from its actual terminal and
final cumulative offset; it never supplies an expected word or a guessed prior.

`CopyConstructorStorage400` exposes the pre-score constructor snapshot.
`CopyScoredStorage400` exposes actual08/10/14 numerical writes and the typed
owners above. `CopyNormalizedScoreStorage400` separately applies273.V60 and
the0C/TOP80 scalar channels, with fresh oldTOP80=-1 from13B870. For this first
alternative the reference makes path10=0/raw mass08=1; singleton publication
makes08/0C=1 and leaves the -1 TOP80 sentinel. None is acceptance confidence.

The numerical normalized storage is explicitly prequote. It does not imply
that native intervening duplicate/exclusion, quote, result normalization or
failure branches executed. WORD identities are genuine live pool identities;
copied numeric/beam arrays are immutable snapshots, not an immutable text pool.
The existing root compositor and callback implementations are unchanged.

## Verification and limits

The headless probe uses one original four-node fixture and nine recorded input
tracks. Pen-up is absent in those records; one unsegmented path per track is an
explicit diagnostic assumption. Expected transcriptions are never read.
Each actual source produces64 snapshots with distinct explicit400-byte residues.
This is640 snapshots across ten sources, not640 different recognized texts.
Both Managed and Windows Native AOT execute this route, retaining the real
terminal/session/pool/WORD/beam identities. The independent Python byte oracle
checks constructor, scored and normalized allocations, including inactive
capacity:76800 bytes per input,768000 bytes across ten inputs.

Fourteen extent/null/cancellation/incomplete/foreign/token-list/publisher
mutation guards run per input. An actual same-pool append after completion is
refused. Returned-array mutation cannot alter the snapshot. The postpublication
beam is compared against its owning materialization; only6/22 metadata may
change relative to the earlier terminal diagnostic row.
There are140 guards across the ten sources. Managed and Native AOT captures are
byte-identical for every source.

The static audit pins six PE regions,26 instructions/blocks and the class279
constructor binding. It checks capacity-round10, first ordinal increment,
in-place constructor, fresh count0/capacity0, fresh99/A8 zero producers, first-reference store, actual
2310 load, selected-beam pointer store, actual279Head18 prepend and freshTOP80=-1. Vendor DLLs are only
read as bytes and are never loaded or executed.
