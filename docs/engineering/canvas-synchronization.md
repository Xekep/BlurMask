# Синхронизация отдельной доски

Сервер синхронизирует только отдельную доску с явно включённой совместной работой. Экранный документ и исчезающие пометки остаются локальными. Приложение и сервер используют общий исходный код из [`NovaPen.Shared`](../../src/NovaPen.Shared/): снимки, изменения, live-контракты, валидацию и сериализацию.

| Слой | Владелец |
|---|---|
| Окно доски и применение результатов на UI-потоке | `CanvasWindow` |
| Локальный снимок, базовая ревизия и ожидающее изменение | `CanvasState` |
| Вычисление разницы и перебазирование локальных изменений | `CanvasMerge` |
| Создание, чтение и сохранение через HTTP | `CanvasCloudClient` |
| Временные штрихи и уведомления по WebSocket | `CanvasLiveClient` |
| Постоянные изменения PostgreSQL | серверный `BoardStore` |
| Участники и временные события | серверный `BoardLiveHub` |

HTTP хранит завершённые изменения, WebSocket снижает задержку представления. Live-превью не является подтверждением сохранения. Пропущенная ревизия или разрыв соединения требуют восстановления из постоянного состояния; ожидающие локальные операции не должны теряться при перечитывании удалённой доски.

Изменения содержат идентификатор операции. Сервер проверяет право доступа и применяет операцию в транзакции, защищая от повторного применения. Ключи приглашений разделяют права просмотра и редактирования. В базе хранятся хеши ключей, а не открытый список пользовательских приглашений.

`BoardLiveHub` хранит временное состояние в памяти одного процесса. Масштабирование на несколько серверных реплик потребует общего транспорта событий; готового брокера в проекте нет. Веб-страница сервера — страница загрузки и передачи приглашения приложению, а не редактор.

Схема зависимостей — в [архитектуре](architecture.md); HTTP-маршруты, лимиты, восстановление и резервные копии — в [развёртывании и API](deployment.md).
