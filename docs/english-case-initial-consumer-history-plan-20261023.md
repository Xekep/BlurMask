## First executable join

The next owning operation must be reserved BEFORE its fresh first-query pass is
run. Native 1FD240 consumes every returned 32-byte row before advancing Q.skip
at controller1680 and fetching another page. The current query-only component
advances Skip immediately after preserving a page. That is correct for its stated
prefix, but a decoder cannot consume those already-completed pages afterward and
claim native interleaving or fault semantics.

Propose an optional private typed consumer on that same internal pass. It receives
the exact active InitialQueryLease and privately issued page, checks owner/root/
initializer/version/map identity, then executes row processing off the root gate.
Only after the whole page succeeds do ConsumedRows and Skip advance. Completed
query pages remain defensive historical evidence after faults; completed consumer
rows, scoring attempts and accepted heap allocations are separate prefix counters.
The null consumer path must remain byte-for-byte equivalent for all old captures.
No caller delegate, raw32, supplied flags, category, source header or copied receipt
can create this consumer. The factory creates its own fresh pass and cannot adopt
a used pass or a public initializer. The same busy lease blocks D0/score/snapshot.

The existing ordinary startup helper is a prepared numeric component. It accepts
raw pages/controller scalars and a full80-byte residue, and categorically refuses
quotes/protocol symbols. It is NOT an owning adapter for this source.
