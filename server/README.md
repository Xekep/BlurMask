# Kiiko Pen — API и страница скачивания

ASP.NET Core 10 отдаёт API для нативного BlurMask и минимальную одностраничную страницу скачивания для Windows, Linux и macOS. Веб-редактора нет. PostgreSQL хранит полотна, ревизии и идентификаторы операций. Незаконченные линии и фигуры передаются другим участникам через WebSocket примерно каждые 50 мс; завершённые рисунки сохраняются сразу. При исправном канале изменения передаются дельтами, а контрольное чтение выполняется раз в 25–35 секунд с ETag. Опрос раз в 1,3 секунды остаётся для восстановления после разрыва соединения. Требуется протокол `blurmask.live.v2`: старые клиенты отклоняются с HTTP 426. Координаты новых точек и сохранённых дельт передаются двоично с исходной точностью double; JSON содержит стили, фигуры и служебные сообщения.

## Запуск на pen.kiiko.ru

Нужен Linux-сервер с Docker Compose, направленная на него A-запись `pen.kiiko.ru` и доступные порты 80/443. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер. Конфигурация в репозитории сама по себе не публикует сервис и не меняет DNS.

В клонированном репозитории:

```bash
cd server
cp .env.example .env
# Укажите в .env длинный случайный POSTGRES_PASSWORD.
# Например: openssl rand -hex 32
docker compose up -d --build
docker compose logs --tail=100 app caddy
curl -fsS https://pen.kiiko.ru/healthz
```

Caddy автоматически получает и обновляет сертификат. База и приложение доступны только внутри Docker-сети. Если на сервере уже заняты 80/443, подключите приложение к существующему reverse proxy вместо второго Caddy. Для локальных сетей, пересекающихся с `10.78.0.0/24`, замените subnet, адрес Caddy и `TrustedProxy` согласованно.

В BlurMask откройте полотно и нажмите **Совместная работа**. Отправьте пользователю код для рисования или отдельный код только для просмотра. Получатель открывает **Полотно → Меню → Подключить** и вставляет код или ссылку. Кнопка **Копировать ссылку** выдаёт `https://pen.kiiko.ru/#<код>` без параметров. В браузере такая ссылка открывает страницу скачивания с кнопкой копирования приглашения; данные полотна страница не запрашивает. В BlurMask адрес сервера зашит в приложение, поля настройки адреса нет. Поддерживается только новый формат приглашения. Код содержит полный ключ доступа: передавайте его тем, кому хотите дать доступ.

Страница использует локальные CSS и JS без внешних шрифтов и зависимостей. Язык выбирается из английского, французского, немецкого и русского по языку браузера. Кнопки скачивания получают адреса файлов последнего релиза из публичного GitHub API; при его недоступности открывают страницу последнего релиза. CSP разрешает сетевые запросы только к своему серверу и `api.github.com`, inline-скрипты и стили запрещены.

## Локальная разработка

Требуются .NET SDK 10 и запущенный PostgreSQL. Node.js 22 нужен только для тестов, npm-зависимостей нет.

```powershell
cd server
$env:ConnectionStrings__Postgres='Host=127.0.0.1;Port=5432;Database=kiiko_pen;Username=kiiko_pen;Password=YOUR_PASSWORD;Maximum Pool Size=20'
$env:PublicUrl='http://127.0.0.1:5079'
dotnet run --urls http://127.0.0.1:5079
```

Откройте `http://127.0.0.1:5079`. В нативном диалоге подключения для localhost разрешён HTTP. Для других адресов требуется HTTPS. Таблицы создаются при старте; нужен пользователь БД с правами на создание таблиц в выбранной схеме.

```powershell
node --test tests/invite.test.mjs tests/landing.test.mjs
$env:PEN_TEST_URL='http://127.0.0.1:5079'
node --test tests/api.test.mjs
node --test tests/live.test.mjs
node --test tests/security.test.mjs
```

Нативная проверка облачной синхронизации запускается из корня репозитория с `BLURMASK_TEST_SERVER=http://127.0.0.1:5079` и аргументом `--isolated-smoke-test`. Этот аргумент предназначен для тестов: он обходит ограничение одного экземпляра.

## Доступ и хранение

- У каждого полотна два случайных ключа: для редактирования и для просмотра. Любой обладатель ссылки получает указанный доступ. Аккаунтов, каталога публичных полотен и совместной авторизации нет.
- Максимальный размер запроса и сохранённого документа — 4 MiB; одновременно обрабатывается не более восьми запросов к backend. Некорректный ключ отклоняется до разбора JSON и обращения к БД. Пустые изменения не увеличивают ревизию и не создают записи в журнале повторов.
- Живой канал использует отдельные настраиваемые пределы: по умолчанию 4096 подключений на процесс, 128 на полотно и 1024 на IP (`Live__MaxConnections`, `Live__MaxPerBoard`, `Live__MaxPerAddress`). Это защитные пределы, а не гарантия пропускной способности. Просмотрщики получают штрихи, но не могут их отправлять. Ключ передаётся заголовком `Authorization`, браузерные подключения с `Origin` отклоняются. Входящий пакет — до 64 KiB/512 точек; до 40 сообщений/с с запасом 80, до 1 MiB/с с запасом 2 MiB. Очередь медленного получателя ограничена 64 пакетами / 128 KiB, после переподключения клиент получает текущие штрихи. На полотно приходится до 40000 временных точек. Незаконченный штрих не записывается в БД, исчезает при отмене/отключении и через 30 секунд без обновлений; неподвижный активный штрих продлевается служебным сообщением каждые 2 секунды.
- Ключи в URL находятся после `#`, в API передаются через `Authorization: Bearer`. В базе хранятся SHA-256-хеши ключей; восстановить потерянную ссылку через список полотен нельзя. Клиенты сохраняют ссылки локально.
- Операции применяются в транзакции с блокировкой строки полотна. Повтор запроса с тем же `operationId` не применяется второй раз. Удаление и отмена затрагивают конкретные идентификаторы штрихов; чужие новые штрихи сохраняются. Одновременное изменение названия/фона использует последнее применённое значение.
- Полотно содержит до 5000 штрихов, суммарно до 200000 точек, до 20000 точек в штрихе. Текст — до 4000 символов. HTTP-запрос — до 4 MiB. Создание ограничено 20 полотнами в час на IP; API — 50 запросами в секунду с запасом 100.
- При отсутствии соединения новые операции остаются в приложении и отправляются при восстановлении соединения. Нативный кэш: `%LOCALAPPDATA%/BlurMask/canvas.json`; перед сменой/созданием полотна сохраняется резервная копия. История undo хранится только в текущем сеансе.
- Экранные пометки не отправляются на сервер. Сайт не хранит локальные полотна и не читает их через API.

Данные сохраняются в Docker-томе `postgres_data`. Для резервной копии:

```bash
docker compose exec -T postgres pg_dump -U kiiko_pen -d kiiko_pen -Fc > kiiko-pen.dump
# Восстановление заменяет содержимое БД; используйте на нужном сервере:
docker compose exec -T postgres pg_restore -U kiiko_pen -d kiiko_pen --clean --if-exists < kiiko-pen.dump
```

Не удаляйте Docker-том базы при обновлении. Сервис не выполняет автоматическое удаление старых полотен; срок хранения и резервные копии настраивает владелец сервера.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/boards` | Создать: `{title,background}`; получить полотно и две ссылки |
| GET | `/api/boards/{id}` | Получить полотно по edit/view-ключу |
| GET (WebSocket) | `/api/boards/{id}/live` | Живые штрихи и уведомления о сохранении, edit/view-ключ в заголовке |
| POST | `/api/boards/{id}/changes` | Применить `{operationId,add,remove,title?,background?}` по edit-ключу |
| GET | `/healthz` | Проверить доступность базы |

Формат данных общий с приложением: `../Shared/BoardContracts.cs`. Страница скачивания использует ES-модули без сборщика и внешних CDN.

Живой протокол описан в `../Shared/LiveContracts.cs`: `preview` передаёт метаданные штриха и новые точки с `offset`; у фигур `offset: 0` заменяет текущую геометрию. Сервер назначает идентификатор участника, отправляет `ready`, `clear` и `changed` с ревизией. Очистка сохранённого штриха применяется клиентом после получения этой ревизии, чтобы он не пропадал между предпросмотром и загрузкой документа. `touch` продлевает неподвижный штрих. Рисование текста, перемещение и стирание сохраняются после завершения операции; исчезающие чернила остаются локальными.

Caddy из этого репозитория поддерживает WebSocket автоматически. В существующем nginx для `/api/boards/.../live` нужны `proxy_http_version 1.1`, заголовки `Upgrade`/`Connection: upgrade`, отключённая буферизация и `proxy_read_timeout 60s`. Ping/Pong каждые 10 секунд поддерживает соединение. Канал рассчитан на один экземпляр серверного процесса: несколько реплик потребуют общего брокера временных событий.

Уведомление `changed` содержит `baseRevision` и `patch` для последовательной ревизии. Пропуск ревизии, большой пакет или изображение вызывают обычное HTTP-чтение. Старые клиенты продолжают читать полотно по HTTP. Пакет кодируется один раз для всех получателей; каждое полотно имеет свою блокировку, а буфер приёма начинается с 4 KiB.

Нагрузочные сценарии и измерения: [docs/performance.md](../docs/performance.md). Граничные локальные тесты `live.test.mjs` используют `Live__MaxConnections=64`, `Live__MaxPerAddress=16`, `Live__MaxPerBoard=16`; в CI эти значения заданы явно.

Для теста общего бюджета временных точек также задаются `Live__MaxPreviewPoints=40000` и `PEN_TEST_PREVIEW_CAP=40000`. В обычной конфигурации бюджет равен 2000000 точек на процесс; счётчики освобождают его при отмене, сохранении, истечении срока и отключении. Предел 40000 точек на отдельное полотно сохраняется.
